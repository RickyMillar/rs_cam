## Invariants
- Every edit writes through the core command path. The tool editor keeps optional non-centre-cutting measurements in its draft; it never invents a measurement. Helix r: None = rule. Ramp angle (P29-8 8b): empty = the rule of the stock material, the hint names its value and source (`ramp_rule_hint`). The stock refit (`panel_apply.rs`) reads core `session::auto_stock_bbox` (F31, every model). The inspector nests ONCE.
- R2/6.F4: the header Tool row greys each tool of `ToolpathPanelInputs::tool_refusals` (core `tool_fit`); `no_tool_state` is its hover (lib `the_tool_picker_greys_refused_tools_r2`). R3: the panel never writes `show_reach_map`; the Reach row asks, `draw_toolpath_selection` calls `registry::set_overlay`. The toolpath panel takes `ToolpathPanelSnapshot` and `ToolpathPanelInputs`. Add a field there, not a
  parameter. Width: not from tab or content (F22); "Done · <danger>" (K6: the export danger chip word; "BLOCKED" is gone) never truncates (figures drop).
  W2b/W3f: `placement::place(list, op)` reads `Diagnostic.anchor`: Tool → Tool row; Field → its `PropRow` when `field_tab(key, op)` names a tab (that tab gets the dot), else the issue stack (no dot); Operation → issue stack; Note/Info/Hint → `NotesCounter`; Project/View/not current → nothing. `field_tab` mirrors the tab predicates (peck only Peck/Chip-break, no scallop row on Drop Cutter, 3D Rough Entry style on Passes); lib `drawn_field_rows_match_the_painted_rows_w3f` draws every tab headless (`record_drawn`) and holds it for each core `anchor_field_names` key.
- A panel door marks the project edited on success; `app.rs` guards on it. R7b: `write_entry_config_to_session` puts `Effects::picks_dropped_note` in `panel_side_effects.notes` (the Input combo; the next frame re-reads the entry). R7a: the boundary source buttons write `BoundaryConfig::with_source` (lib `the_selection_source_button_drops_the_diameter_offset_r7a`). A pinned Bottom Z note names
  the ops that `capabilities().floor_owner` does not mark `HeightsBottom`. D6/Q8: an `OpFloor` op (the Drill too, F19) has ONE floor editor, "Bottom height" on the Heights tab under "Top height" (`draw_bottom_height` via `BottomHeight`; `Floor::row_references(item_use)`, no "A picked face"; G-DEPTHSTOCK = its Caution state); no Floor line, `OpDrawCtx` has no `floor`; a reference change and a diagram drag use `FloorReferences` (L-10) on one draft floor. W3d: every height is ONE `PropRow` column: absolute Z (= diagram = MCP), unit "mm", a reference combo (Auto/reference); notes, F033 refusal (`HeightsRefusal::field`) and L-4 are row state/hover; the diagram face has values, names on hover. The diagram floor runs come from `floor_runs` (`FloorInputs::face_floors`: Z and face count); every run has a hover. F033: every heights write (a row, an Auto button, a diagram drag and its rounding) goes through `admit_heights_edit` (core `ToolpathHeights::edit_refusal`); the badge is `height_order_badge`; the refusal text is GUI state (`state.panels.heights_refusal`, scoped to the toolpath), not egui memory (ui09).
  "Show me" frames `selection_highlight::note_item_keys`: the skipped items of a note's kind and layer, or the one face of an at-the-top note.
- A draw never writes `rest_analysis.enabled`; `apply_auto_enable` is the door. A tooltip keys on the registry parameter NAME, never the label.
- W6: the inspector (R5: the toolpath panel files) draws kit rows only, no raw label/horizontal/Grid/DragValue/checkbox/ValueRow/param_grid (`the_inspector_draws_only_kit_rows_w6`; its allow-list only shrinks). A finding reaches a panel only as `placement::Finding` (its `Diagnostic` is private); notes paint only in the `StatusLine` counter; the stack is 3 rows + blockers (`the_issue_stack_is_capped_w6`); no W0 text over 60 chars (IC1 `_w6`).
- `geometry_tab.rs` writes `EditToolpathSelection`, `UseAsFloor`, `ClearFloorFace` only (L-1), never the draft; the Input and boundary rows beside it do. The Profile Tabs
  row toggles the tab editor (`OpDrawCtx::selection_ui`); the editor writes `EditTabs`.
- F216: the pills and the feeds rows of Passes read `entry.feeds_memo` (P5b: the envelope too, `FeedsMemo::envelope`; the candidate ring is `state.panels.envelope_candidates`, threaded in as `heights_refusal` is). A new feeds input goes in `FeedsInputs`, not a second read. P29-9: `ToolpathPanelSnapshot::suggest_slots` is the session door (`ProjectSession::suggest_slots`); the memo, the pills, the envelope and the card build the context with `SuggestSlots::context(&entry.dressups)` (`FeedsInputs::context`), never a context of their own (`the_gui_reads_the_session_suggest_door_p29_9`). W3i feeds rows (on Passes since P5b): speed `PropRow`s (⚡ = a Suggest stamp, R1), a Chipload row, the chart inline, the card's ONE `Details`, `Vendor data…` window (`ui/feeds/`); W3k: `PropRow::lock` padlock on Feed/Spindle/Chipload, `write_speed_edit` writes the edit + dependent (core `FeedsLock`). W3g: no Cut row; the cut suggestion is the "⚡ 0.83" action of a `dv_pill` row (`suggest_action`); a rule hint shows no unit.
- One `OpUiRow` per op carries the editor, the diagram decision and the validation arm. F12: a diagram draws the op's real data (Drill, Pin Drill: `OpDiagram::Holes`, the drilled holes; Pin Drill reads core `pin_drill_holes`) or the row is `OpDiagram::None` (reason in code); no diagram = no box, no sentence.
- IC1/IC2: a field is one row, its explanation the hover. Derived data is `DataTable` rows, derivation in ONE
  `Details`; only a blocking error wraps (`DANGER`). A finding has one place (`place`). Rare dials go in
  the tab's ONE `advanced` section. A diagram comes before its rows.
