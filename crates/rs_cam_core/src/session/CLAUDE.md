## Invariants
- A command returns `Effects`; `Effects.stale` is the stale set. Do not add a setter without a command row (the registry test fails). There are no public `*_mut` hatches (`setups_mut` is `#[cfg(test)]`).
- `ApplyFeeds` is the one Apply-Suggest row (F114; GUI, MCP, CLI); `suggest_slots` is the one Suggest context of a toolpath and `new_op_suggest_slots` the one of a new op (P29-9: `draft_toolpath`, `tool_fit` with the op's setup, the pin drill, the multi-tool tiers, the CLI smoke). On a tool change `seed_geometry` then `seed_feeds` fill each empty or suggested field; a Manual, AutoCorrect or unstamped value stays; with no basis a suggested field clears (no underived defaults).
- S11: generation refuses in this order: stock with no `z`, a depth, the floor, a required tool fact (D12), the feeds. A file with no stock `z` or op `floor` loads them unset.
- An edit invalidates the result chain to fixpoint (`invalidate_output_dependents_of_set`); an S2 stock change drops from its setup on (`drop_stock_change_dependents`). `dependencies::edges` and `generation_plan` are the rules; no surface re-derives them.
- `drop_simulation(cause)` is the one site that clears the simulation (bumps `simulation_epoch`); `store_simulation` is the one store. `AdoptResult` refuses a stale revision, `AdoptSimulation` a stale epoch; with a `FeedModulation` it modulates after the epoch check (F115). A slot is `Dressed` until modulation rewrites it; every export reads `feed_stage` (W2.5).
- P31 C (operator ruling 2026-11-15): one stored `feed_modulation` switch (`FeedModulationSwitch`, default on, `[job.simulation] feed_modulation`); `SetFeedModulation` writes it, drops the simulation (`SimulationDropCause::FeedModulation`) and, with the switch off, puts the dressed path of each modulated result back (`ResultProvenance::Modulated { dressed }`; `Effects::modulated` names them). `modulate_simulation_trace` runs only while it is on, and `run_modulation_of` is `Off` while it is off. `EmittedFeeds::above_stated_warning` is THE text of `export.feed_above_stated`. Sentry: `feed_modulation_is_a_project_switch_p31`.
- One stored `simulation_resolution` sets every cell. A rest result whose `SourceStock` no longer matches drops (G-RESTRES). Read `ProjectSession::simulation_triage`, not a raw issue count. A surface that walks every toolpath with a held trace calls `diagnose_toolpath_with_held_trace` (the memoised load report: one build for the walk, `--lib a_diagnostic_walk_with_a_held_trace_builds_the_report_once`), never `diagnose_toolpath_with_trace` in a loop.
- Generation passes `entry_feed_rate()` and the STOCK top (never `heights.top_z`) as the descent ceiling.
- Load: a bare tool fact refuses (`BareToolFacts`, one message names every key); each `RETIRED_KEYS` / `RETIRED_OP_ENTRIES` key refuses (`RetiredKeys`, one message); every section but the toolpath and op tables is `deny_unknown_fields`; an unknown datum refuses; an unknown tool type, material or cut direction warns and defaults. `model_id` is required; `tool_id: Option` (`NoTool` refuses generation, export, Suggest); a repeated id refuses; a value outside its domain refuses at its door and at load (`OutOfDomain`). A lower error stays typed (`SessionError::Operation`, `Selection`, `Obstacle`, `Export`): match the variant, never the text.
- Heights: `heights.rs` is THE heights rule; every other surface reads `toolpath_heights` (`Peek`). `clamps_face_top` (`FaceTopRule`) and `depth_base_z` set the face top; a buried face is a warning (K6). The op `Floor` resolves into `HeightContext::floor`; a floor that does not resolve or sits at or above the top refuses generation. `set_toolpath_floor` is the door of `SetToolpathFloor`. Per-face and per-hole floors come from the report (`region_floors`, `hole_floors`). The floor-due rules: `each_face_floor_due`, `part_outline_floor_due`, `each_hole_floor_due`. A height-order break warns, never refuses (F033, K6).
- Selection: a model id and a tool id are EXACT. `SessionError::Selection` = generation = `selection_status` (H1: the op report runs `selection::op_items`). A click goes through `pick_edit` / `click_edit`; `edit_toolpath_selection` is the batch door (an `AddPick` key must name one item, SEL-4; a rule drop becomes one `Replace`, GT-Q8). A model change runs `drop_lost_picks`. `ToolpathConfig::models_read` drives `drop_results_for_model`.
- Faces and picks: generation `Build`s STL flat faces, every other read `Peek`s (P4.7). `LoadedModel::ray_pick` is the one mesh-pick door; it never builds. `adopt_geometry` replaces the import options and replays the drawing ledger (stored in file units).

- `Peek` on every read but generation: a `Build` on the frame stalls the GUI.
- `session/compute.rs` is large; a new stage goes in `session/compute/`, not in the facade.
