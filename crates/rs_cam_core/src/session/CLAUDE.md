# `session/` — `ProjectSession`, commands and effects

The one door for project state and compute is `ProjectSession::apply(Command)`.

## Files

- `mod.rs` — `ProjectSession` and the facade. `command.rs` — the registry and the `Effects` door. `dependencies.rs`, `generation_plan.rs` — edges, order.
- `mutation.rs`, `mutation/` (CRUD, S2 `stock_change.rs`); `compute.rs`, `compute/` (generation, simulation, export (F121: also the freshness rule `sim_trace_is_fresh(_for)` and `build_tool_load_report`), diagnostics, `params.rs` the parameter setters); `builder.rs`, `project_file.rs`, `save.rs`;
  `stock_change_report.rs` (S4 rows); `diagnostics_types.rs` (keep the `mod.rs` re-export).
- `eval_context.rs`, `cycle_time.rs`, `reach.rs`, `multitool.rs`, `pins.rs` (P6 pin inputs, P10 setup notes), `pin_report.rs` (P7, the one pin report); `shoe.rs` (H1, the one shoe plan); `rest_fresh.rs` (the fresh twin of a rest op, on request); `rest_stock.rs` — the
  stored resolution; `auto_stock.rs` (F31: THE auto stock rule, `fit_auto_stock` = `update_from_bbox` of the union of EVERY model box (not the pin part set: it reads the stock); add, remove, adopt, drawing edit and load call it; a moved stock drops every result; `auto_from_model` false never moves); `load_report.rs` — the memo; `result_provenance.rs` — the feed stage (W2.5); `heights.rs` (THE heights, the floor door); `selection_status.rs` (P2.4: THE resolution, the `SelectionStatus` memo; GT-2 `SelectedRow` rows); `rule_offers.rs` (GT-3: `rule_offers`, the facts of ONE picked item, members by `rule_members`, one `Replace`); `tab_layout.rs` (P4.6: the `TabLayout` query, no kernel; `apply_tab_edit`: L-5 conversion, O-4 refusal); `op_draft.rs` (S11 parity: `draft_toolpath`, THE draft of a new op for the GUI, MCP and the CLI: stock defaults, Suggest, `DressupConfig::for_op`, the 3D boundary; `Unbacked` gives no feeds).

## Invariants

- A command returns `Effects`. `Effects.stale` is the stale set. F114: `ApplyFeeds` is the one Apply-Suggest row (GUI; MCP through the controller; CLI); `suggest_slots` is the one Suggest context assembly. F040: `PlanMultitoolFinishing` is the planner row (one `Effects` window, the outcome on `Effects::planned`). P6.7: `AddBoreFromDrill` (index + typed id; `NotADrill`, `ToolpathIdMismatch`) adds one Bore after the Drill (`mutation/toolpath.rs`). F215: `SessionError::field` (exhaustive) names the refused field.
- S11: generation refuses in this order: `stock_thickness_refusal` (a stock with no `z`), a depth (`NotSet`), the floor (`FloorRefusal::Unset`, heights door), the feeds (`cut_feeds`). A file with no stock `z` or op `floor` loads them unset; a saved value stays.
- An edit invalidates the result chain to fixpoint: `invalidate_output_dependents_of_set`; an S2 stock change, from its setup on: `drop_stock_change_dependents`.
- `dependencies::edges` (rules), `generation_plan` (order; a row that gains a result in the plan stales the snapshots below it, W1.5b): no surface re-derives either. `walk_output_dependents` drops results and touches no simulation; an edit takes `invalidate_output_dependents_of_set`.
- `drop_simulation(cause)` is the one site that clears the simulation. It
  bumps `simulation_epoch` and records the cause. `AdoptResult` refuses a
  stale revision, `AdoptSimulation` a stale epoch. `store_simulation` is the one
  store; it numbers the run. W2.5: a slot is `Dressed` until modulation rewrites it (`Modulated
  { simulation_run, source }`, B5: current while `source` is); every export reads `feed_stage`. F115: `AdoptSimulation` with a `FeedModulation` modulates after the epoch check, before the store (the `run_simulation` order); `Effects::modulated` names the rewritten indices.
- ONE stored `simulation_resolution` sets every cell. F020: `SimulationOptions::resolution` is a `SimulationResolution`; `resolution_mm` resolves it and the stored value by one rule. `try_with_effects` drops a rest result whose `SourceStock` no longer matches (G-RESTRES).
- There are no public `*_mut` hatches. `setups_mut` stays `#[cfg(test)]`. Read `ProjectSession::simulation_triage`, not a raw issue count; its entry points pass `rough_coverage_readings` (G-ROUGHCOV, `compute/simulation.rs`: the stored run's checkpoints, only when its boundaries are the evidence's).
- Generation passes `entry_feed_rate()`, not the raw ramp feed (G10 B4), and
  the STOCK top, never `heights.top_z`, as the descent ceiling (G-PECKSPLIT).
  Do not add a setter without a command row. The registry test fails on it. C1: the loader refuses each key in `project_file::RETIRED_KEYS` (a key that leaves the format gets a
  row; a key that leaves some op kinds only is a `RETIRED_OP_ENTRIES` row: `depth` and a pinned `bottom_z` on the four floor ops); C2: one refusal names EVERY retired key in the file (`SessionError::RetiredKeys`).
  F034: every `project_file` section except the toolpath section and the op tables is `deny_unknown_fields`;
  the retired-key check runs on the raw table first. F015: an unknown datum token refuses
  (`UnknownSetupDatum`); `from_key` returns `Option`. F053: `tool_id`/`model_id` required; a repeated id refuses (`DuplicateId`). W6b: an op, stock, machine, head or shoe value outside its domain refuses at its door and at load (`SessionError::OutOfDomain`, `compute::domain`). F054: a lower error stays typed (`SessionError::Operation` by `From<OperationError>`, a selection goes to `Selection`; `Obstacle`; `Export`); match the variant, never the text. F055: a missing model id is `ModelNotFound`; `collision_check` gives `Ok(None)` when nothing can be hit.
- Heights: `heights.rs` is THE heights rule (setup-frame mesh box, `HeightsConfig::resolve` (`pub(crate)`), auto top = the highest up-face top; UX-1/UX-1b: `clamps_face_top` reads `Capabilities::face_top` (`FaceTopRule::HigherOfFaceAndStock`: the `OpFloor` ops, Face, Trace) and makes it the higher of that and the stock top; `depth_base_z` (the face top) is the base of `Floor::Top`, of the auto bottom and of `ResolvedHeights::depth_base_z`, which `cutting_levels` and the Face ladder step to; UX-1c: `FaceTopRule::RefuseBuried` (V-Carve, Inlay, Inlay Plug; Chamfer is `RefuseBuriedEach`, R-C: its LOWEST item, `face_bottom_z`) keeps the face top and `ToolpathHeights::buried_face_refusal` refuses a face below the stock top on fresh stock at generation and in the diagnostics (`precondition.buried_face`); the prologue owns "After previous ops"; a pinned top never refuses; `TopSource`). Generation calls it; every other surface (the GUI, MCP diagnostics via `from_toolpath_heights`) reads `toolpath_heights` (face top from the memo, `Peek`). L-4: a Model Top/Bottom Top or Bottom Z on a toolpath with no mesh refuses generation (`model_reference_refusal`). The op `Floor` resolves into `HeightContext::floor`; a floor that does not resolve, or sits at or above the top, refuses generation (`floor_refusal`, L-16; under `EachFace` it checks the DEEPEST face floor). `ToolpathConfig::floor_conflict` refuses a pinned Bottom Z on an `OpFloor` op at `set_heights_config`, `ReplaceToolpathConfig`, the op change, `add_toolpath` and generation (the builder is raw). `set_toolpath_floor` (in `heights.rs`) is the door of the `SetToolpathFloor` row (MCP, CLI; the GUI sends the whole config, L-17): it refuses `Floor::door_refusal` and runs `domain::validate_toolpath_operation` on the candidate config. UX-8: under `Floor::Face` the key resolves as a one-pick selection (`floor_face_z`; generation `Build`, every other read `Peek`); a key that does not resolve refuses generation and `selection_status` with `RefusalCause::FloorFaceLost` (or `AmbiguousPick`, `FaceFacesDown`); `set_toolpath_floor` stores the key in the toolpath form and drops it from the picks (L-R5); `cleared_floor` is the GT-4 Clear. `ToolpathHeights::floor_z` reads the resolved floor; `floor_references` feeds the GUI L-10 rule. Under `EachFace` (L-15) the auto top is the stock top and the floor is `FloorRef::EachFace` (face planes from the report's `face_top_z`/`face_bottom_z`). The report runs `region_floors` with `each_face_top_z` (the memo key holds the floor and Top Z), applies the skip (notes, `Skipped` state) and gives `item_floor_z`/`foreign_floor_z`; generation leaves `NoFace`/`AboveTop` to the prologue. `params.rs`: `set_toolpath_param depth` on an `OpFloor` op names `set_toolpath_floor`. R-B/F19: the report gives `hole_rim_bottom_z`/`hole_floor_bottom_z` (setup frame) and runs `hole_floors` on `heights_in_setup` (memo key: floor + Top Z); `FacePlanes` carries them to `toolpath_heights` and generation; an auto `Top` floor on rims is `FloorRef::PerHole` (lowest rim less depth); `TopSource::AutoHoleRims` ("auto: hole rims"); `each_hole_floor_due` sets `EachHole` on a default Drill floor (`Effects::floor_set_note`); generation leaves `NoHoleDepth`/`AboveTop` of each hole to the prologue; `hole_rim_key` maps a click on a floor circle to its rim (`pick_edit`); R-E: `HoleSummary`/`hole_label` ("Ø6 hole, 8 deep"), `fold_hole_floors` on `rows` and `list_model_items`; `RETIRED_OP_ENTRIES` has the Drill `depth` (stock_top text) and pinned `bottom_z`; `AddBoreFromDrill` copies the floor and heights. F033 (ruling 2): `ToolpathHeights::height_order` reads THE order rule (`compute::config::height_order`); `height_order_door` refuses an edit that ADDS a refusing break (`SetToolpathHeights`, `ReplaceToolpathConfig`; not `AddToolpath`, not `SetToolpathFloor`); generation refuses every refusing break (`SessionError::HeightOrder`; under `EachFace` the prologue owns the bottom break); `height_order_refusal` is the export row.
- P2.4/P2.5: a model id and a tool id are EXACT (no first-item fallback); `SessionError::Selection` = generation = `selection_status` (Chamfer Clearance: the report runs THE wall trim, `clear_edges_as_generation`, on the setup mesh and the built cutter; key `StatusKey.edge_clear`); `ToolpathConfig::models_read` drives `drop_results_for_model` (re-import AND `remove_model`, P2.6). GT-Q8: `edit_toolpath_selection` turns a `RemovePick` of a rule item into one `Replace` (`rule_drop_edit`: each rule that holds it becomes picks of its members; a default rule's members are its `Cut`/`Island` items). P4.3: the `SelectionStatus` query answers the memo's `Arc` (no clone per frame); the GUI Selection section reaches it and `ListItems`. P4.8: `LoadedModel::import_options` (`[models.import]`, serde default, no key at the default) and `import_report` (not saved); `adopt_geometry` REPLACES both, so a refresh door imports with the record's options; the `AdoptModelGeometry` row is the MCP tool `set_model_import_options`. P4.9: `LoadedModel::drawing` (the edit ledger, `[[models.drawing_edits]]`, no key when empty) is KEPT by `adopt_geometry`, which replays it on the fresh door items; `EditModelDrawing` (`LedgerEdit::{Add, Remove, Replace}`; an `Add` that does not apply refuses) replays and drops the model's readers. The file stores the ledger in FILE units (the `[models.import]` tolerance frame): `Add` takes model mm and converts once (`drawing_scale`), `Replace` takes file units; `adopt_model_geometry` sets the units BEFORE the adopt, so a rescale replays at the new scale and changes no stored edit.
