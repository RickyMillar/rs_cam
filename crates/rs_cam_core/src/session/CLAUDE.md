# `session/` — `ProjectSession`, commands and effects

The one door for project state and compute is `ProjectSession::apply(Command)`.

## Files

- `mod.rs` — `ProjectSession` and the facade. `command.rs` — the registry and the `Effects` door. `dependencies.rs`, `generation_plan.rs` — edges, order.
- `mutation.rs`, `mutation/` (CRUD, S2 `stock_change.rs`); `compute.rs`, `compute/` (generation, simulation, export (F121: also the freshness rule `sim_trace_is_fresh(_for)` and `build_tool_load_report`), diagnostics, `params.rs` the parameter setters); `builder.rs`, `project_file.rs`, `save.rs`;
  `stock_change_report.rs` (S4 rows); `diagnostics_types.rs` (keep the `mod.rs` re-export).
- `eval_context.rs`, `cycle_time.rs`, `reach.rs`, `multitool.rs`, `pins.rs` (P6 pin inputs, P10 setup notes), `pin_report.rs` (P7, the one pin report); `shoe.rs` (H1, the one shoe plan); `rest_fresh.rs` (the fresh twin of a rest op, on request); `rest_stock.rs` — the
  stored resolution; `load_report.rs` — the memo; `result_provenance.rs` — the feed stage (W2.5); `heights.rs` (THE heights, the floor door); `selection_status.rs` (P2.4: THE resolution, the `SelectionStatus` memo); `tab_layout.rs` (P4.6: the `TabLayout` query, no kernel; `apply_tab_edit`: L-5 conversion, O-4 refusal).

## Invariants

- A command returns `Effects`. `Effects.stale` is the stale set. F114: `ApplyFeeds` is the one Apply-Suggest row (GUI; MCP through the controller; CLI); `suggest_slots` is the one Suggest context assembly. F040: `PlanMultitoolFinishing` is the planner row (one `Effects` window, the outcome on `Effects::planned`). P6.7: `AddBoreFromDrill` (index + typed id; `NotADrill`, `ToolpathIdMismatch`) adds one Bore after the Drill (`mutation/toolpath.rs`). F215: `SessionError::field` (exhaustive) names the refused field.
- An edit invalidates the result chain to fixpoint: `invalidate_output_dependents_of_set`; an S2 stock change, from its setup on: `drop_stock_change_dependents`.
- `dependencies::edges` (rules), `generation_plan` (order; a row that gains a result in the plan stales the snapshots below it, W1.5b): no surface re-derives either. `walk_output_dependents` drops results and touches no simulation; an edit takes `invalidate_output_dependents_of_set`.
- `drop_simulation(cause)` is the one site that clears the simulation. It
  bumps `simulation_epoch` and records the cause. `AdoptResult` refuses a
  stale revision, `AdoptSimulation` a stale epoch. `store_simulation` is the one
  store; it numbers the run. W2.5: a slot is `Dressed` until modulation rewrites it (`Modulated
  { simulation_run, source }`, B5: current while `source` is); every export reads `feed_stage`. F115: `AdoptSimulation` with a `FeedModulation` modulates after the epoch check, before the store (the `run_simulation` order); `Effects::modulated` names the rewritten indices.
- ONE stored `simulation_resolution` sets every cell. F020: `SimulationOptions::resolution` is a `SimulationResolution`; `resolution_mm` resolves it and the stored value by one rule. `try_with_effects` drops a rest result whose `SourceStock` no longer matches (G-RESTRES).
- There are no public `*_mut` hatches. `setups_mut` stays `#[cfg(test)]`. Read `ProjectSession::simulation_triage`, not a raw issue count.
- Generation passes `entry_feed_rate()`, not the raw ramp feed (G10 B4), and
  the STOCK top, never `heights.top_z`, as the descent ceiling (G-PECKSPLIT).
  Do not add a setter without a command row. The registry test fails on it. C1: the loader refuses each key in `project_file::RETIRED_KEYS` (a key that leaves the format gets a
  row; a key that leaves some op kinds only is a `RETIRED_OP_ENTRIES` row: `depth` and a pinned `bottom_z` on the four floor ops); C2: one refusal names EVERY retired key in the file (`SessionError::RetiredKeys`).
  F034: every `project_file` section except the toolpath section and the op tables is `deny_unknown_fields`;
  the retired-key check runs on the raw table first. F015: an unknown datum token refuses
  (`UnknownSetupDatum`); `from_key` returns `Option`. F053: `tool_id`/`model_id` required; a repeated id refuses (`DuplicateId`). W6b: an op, stock, machine, head or shoe value outside its domain refuses at its door and at load (`SessionError::OutOfDomain`, `compute::domain`). F054: a lower error stays typed (`SessionError::Operation` by `From<OperationError>`, a selection goes to `Selection`; `Obstacle`; `Export`); match the variant, never the text. F055: a missing model id is `ModelNotFound`; `collision_check` gives `Ok(None)` when nothing can be hit.
- Heights: `heights.rs` is THE heights rule (setup-frame mesh box, `HeightsConfig::resolve` (`pub(crate)`), auto top = the highest up-face top; `TopSource`). Generation calls it; every other surface (the GUI, MCP diagnostics via `from_toolpath_heights`) reads `toolpath_heights` (face top from the memo, `Peek`). L-4: a Model Top/Bottom Top or Bottom Z on a toolpath with no mesh refuses generation (`model_reference_refusal`). The op `Floor` resolves into `HeightContext::floor`; a floor that does not resolve, or sits at or above the top, refuses generation (`floor_refusal`, L-16; under `EachFace` it checks the DEEPEST face floor). `ToolpathConfig::floor_conflict` refuses a pinned Bottom Z on an `OpFloor` op at `set_heights_config`, `ReplaceToolpathConfig`, the op change, `add_toolpath` and generation (the builder is raw). `set_toolpath_floor` (in `heights.rs`) is the door of the `SetToolpathFloor` row (MCP, CLI; the GUI sends the whole config, L-17): it refuses `Floor::door_refusal` and runs `domain::validate_toolpath_operation` on the candidate config. `ToolpathHeights::floor_z` reads the resolved floor; `floor_references` feeds the GUI L-10 rule. Under `EachFace` (L-15) the auto top is the stock top and the floor is `FloorRef::EachFace` (face planes from the report's `face_top_z`/`face_bottom_z`). The report runs `region_floors` with `each_face_top_z` (the memo key holds the floor and Top Z), applies the skip (notes, `Skipped` state) and gives `item_floor_z`/`foreign_floor_z`; generation leaves `NoFace`/`AboveTop` to the prologue. `params.rs`: `set_toolpath_param depth` on an `OpFloor` op names `set_toolpath_floor`. F033 (ruling 2): `ToolpathHeights::height_order` reads THE order rule (`compute::config::height_order`); `height_order_door` refuses an edit that ADDS a refusing break (`SetToolpathHeights`, `ReplaceToolpathConfig`; not `AddToolpath`, not `SetToolpathFloor`); generation refuses every refusing break (`SessionError::HeightOrder`; under `EachFace` the prologue owns the bottom break); `height_order_refusal` is the export row.
- P2.4/P2.5: a model id and a tool id are EXACT (no first-item fallback); `SessionError::Selection` = generation = `selection_status`; `ToolpathConfig::models_read` drives `drop_results_for_model` (re-import AND `remove_model`, P2.6). P2.6: a click toggles through `pick_edit` (the memo); `face_pick_key`; `list_model_items`; the undo snapshot restores `boundary` (D11). P4.1: `SelectionTarget { Op, Boundary }` names a selection (`ToolpathConfig::selection_of`; the memo keys on it); an op with no slot takes its face picks and auto top from a `Selection` boundary (`boundary_face_top_z`). P4.D (L-8 revised): `click_edit` → `ClickEdit`; a click on a boundary that is not a selection is `BoundaryToSelection` (one `SetBoundaryConfig`, `enabled` kept); `pick_edit` and `EditSelection` keep their refusal. P4.2 (L-6): `pick_edit` gives `Replace` with the one pick while the op selection is `Selection::stock()`. P4.3: the `SelectionStatus` query answers the memo's `Arc` (no clone per frame); the GUI Selection section reaches it and `ListItems`. P4.4: the report gives `item_states` (index-aligned with `LoadedModel::items`) and `foreign`, from the same resolution and the `view` roles; a refused selection marks no item `Cut`. P4.5: `layer_rule_edit` (a shift-click, beside `pick_edit`); `ListItemsArgs.near` (`Near`, model frame) = the click rule. P4.7: `FaceAccess` — generation `Build`s an STL's flat faces before it resolves, every other read `Peek`s; the report gives `faces_not_ready` (no count, no refusal); `face_pick_key_at`; `ListItems` lists STL faces for `kind: face` only (it builds); Job row `build_model_faces`. P4.8: `LoadedModel::import_options` (`[models.import]`, serde default, no key at the default) and `import_report` (not saved); `adopt_geometry` REPLACES both, so a refresh door imports with the record's options; the `AdoptModelGeometry` row is the MCP tool `set_model_import_options`. P4.9: `LoadedModel::drawing` (the edit ledger, `[[models.drawing_edits]]`, no key when empty) is KEPT by `adopt_geometry`, which replays it on the fresh door items; `EditModelDrawing` (`LedgerEdit::{Add, Remove, Replace}`; an `Add` that does not apply refuses) replays and drops the model's readers. The file stores the ledger in FILE units (the `[models.import]` tolerance frame): `Add` takes model mm and converts once (`drawing_scale`), `Replace` takes file units; `adopt_model_geometry` sets the units BEFORE the adopt, so a rescale replays at the new scale and changes no stored edit.
