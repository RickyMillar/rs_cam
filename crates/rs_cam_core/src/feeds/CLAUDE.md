# `feeds/` — feeds and speeds

RPM, feed, plunge, ramp, depth and width for one cut, each with its source. `feeds::suggest` is the validated entry point. This file is the one map of the feeds flow. History: `git log`, `planning/feeds_contract_2026-11-03/`.

## Files
- `mod.rs`, `tests.rs` — calculator types (`FeedsInput`, `FeedsResult`, `FeedsDerates`), helpers, `effective_diameter`. `calculator.rs` + `calculator/` — `calculate_with`, one function per step: `speed.rs` (1-2), `spindle.rs` (5c: `step5c_constant_chip`, the one RPM-choice door; `FeedsResult::rpm_choice` names the binding `RpmLimit` and every limit, `None` under `MatchChart`), `chip.rs` (2), `cut.rs` (3-4c; P16 deleted the Step 4b slot cap), `feed.rs` (5, 5b, 7), `power.rs` (6), `close.rs` (8-9c); `StepLog` writes `FeedsResult::steps`.
- `suggest.rs` + `suggest/` — the Suggest model and doors: `apply.rs` (the write funnel, previews, `funnel_steps`), `invariants.rs` (the speeds chain: passes 1, 9, 10 and the warn-only passes), `axial_envelope.rs`, `adaptive_entry.rs`, `tests.rs`.
- `sourced.rs` (K2: `Sourced<T>`, `Basis` incl. `ToolFact`, `PointBases`, `lower_to_cap`, `Recommendation`), `envelope.rs` (K2b: `SafeEnvelope::for_cut`, `Limit`, `SpeedsMap`, `Placement`, `PickRequest`, `EnvelopePick`, `ENVELOPE_GRID_N`, `refine_budget_columns`), `force_budget.rs` (P13c: `HOBBY_SLOT_POINTS`, `hobby_budget`, `depth_at_budget`, `rigidity_depth_cap`, `COMPUTED_WIDTH_ASSUMPTIONS`).
- `section.rs` (P20d `EngagedSection`: `Rectangle`, `VGroove`, `AxialCircle`; `side_cut` and `axial_plunge` match the hint with no wildcard; `SectionKind::gates`). `engagement.rs` (K7 `Engagement`: `EngagedDiameter`, `from_cut`, `from_tool_cut`, `from_sample`, `edge_force`, `PowerModelInputs`, `PowerCase(s)`), `operating_point.rs` (`power_at_operating_point`, `power_at_shipped_point`, `force_at_shipped_point`, `shipped_power_json`), `force.rs`, `geometry.rs` (diameters, `RadialThinning`), `geometry_class.rs`, `cutter_constraints.rs`, `predict.rs`, `efficiency.rs`.
- `vendor_lut.rs`, `vendor_lookup.rs`, `vendor_normalize.rs`, `series.rs` — the vendor table, lookup, type map, row series. `extrapolation.rs` + `extrapolation/{size,hardness,family,drill,plunge}.rs` — the G1, G2, G3, G6, G10 claims. `ramp.rs` (G6 ramp), `plunge.rs` (G10), `vertical.rs` (P20b: `VerticalRateLimit`, `AxialChipBound`, `ZAxisRate`).
- `profile.rs` (`CutterOpProfile`: the pre-sim view, `shipped_power`), `quantities.rs`, `provenance.rs` (a projection of `FeedsResult::bases`), `support.rs`, `lock.rs` (GUI `FeedsLock`), `rationale.rs`, `feed_explanation.rs`, `explain_payload.rs`.

## Invariants
- Chip first (P11b): Step 5 sizes the feed so the PEAK chip is the band chip. P23a: the lift reads the widest width the planner holds at the full feed, `PowerCases::full_feed_width` (`catalog::PlannerWidth`: the pass ceiling `c D` for 2D Adaptive and geodesic 3D Rough, else the nominal stepover); the `PlannerCap` power case, the unlifted feed, the ladder's width rung, pass 9, `efficiency` and the load context read the same door (sentry `the_lift_reads_the_pass_ceiling_width_p23a`). P23d: the first ring of each level of a contour Pocket (a full slot) is fed at `geometry::UnliftedFeed::of_slot_ring` with `Move::feed_cap` set; Suggest prints it as `SuggestedSpeeds::slot_ring_feed_mm_min` (sentry `a_pocket_feeds_its_slot_first_ring_unlifted_p23d`). `geometry::RadialThinning` is the one thinning rule (Garr `1/sin psi`, no cap; finish pass and drill cycle do not thin); Suggest, `efficiency`, pass 9, the gate, the modulator (band-mid too) and `dressup::feedopt` read it (P14, review M2).
- The printed band holds at every depth: no reader de-rates by depth. `doc_derating_scale` is only the table that `vendor_depth_table_ceiling_ratio` inverts (`LimitKind::VendorDepthTable`). A V-bit row is read at its printed key (B4); a tapered row at its tip (A1).
- A STATED depth ships with its own speeds, above the flute guard, with a warning; only a default depth is lowered. P16 (D12): no slot cap; the force budget sets the slot depth. Suggest writes geometry only on an `EnvelopePick` (K2b); the proposal is `min(stated, binding cap)` (`lower_to_cap`), never a raise. P16: no depth proposal (`ProposedDepth::None`) with no force line or on a surface offset (Project Curve, `Axial::SurfaceOffset`: no pre-sim depth, power, force, deflection or MRR (`Err(DepthAfterSimulation)`); one `DepthJudgedAfterSimulation`); an apply then writes no depth. P19: a drawn envelope edge reads the plane only, never the stated cut. Exact values at the stated or proposal width live in `SafeEnvelope::exact` (`place`, `judged_value`); P19b: a move model that reads the depth (`predict::move_count_reads_depth`) gives `Edge::AeCurve` (a width floor over the depth, `[ap, ae]` samples from the plane, no sample at a depth no width meets), a budget unmet at every point gives an `Unmodelled` `Runtime`, and `place` judges the point by the predicted moves.
- `apply` is THE write (F114); `apply_to_operation` is the funnel of `Command::ApplyFeeds`; every apply door calls `accept_unsourced` (D4: the apply is the acceptance). The pills read `preview_field_applies`.
- K7: one engagement. Every power and deflection reader builds `PowerModelInputs` through `Engagement`; `edge_force` mean = power, PEAK resultant = lateral force; `fz_cap_for_peak_force` is the one feed cap. Pre-sim power is the maximum over the `PowerCases` of the `CutSpec`; a grid point names its case and width (`SpeedsPoint::power_case`, `power_width_mm`, P20i). A measured point's power is the gate's figure (`MeasuredTool::power`), not the drawn edge (P20i). Suggest reads no simulation (Q5).
- P15: one `d_eng` door. Every `Engagement` constructor takes an `EngagedDiameter` (private field): `of_hint` = `effective_diameter`, `of_tool` = `2 x engagement_radius`. Flat, ball and bull arms call the cutter's own width (`tool::ball_radius_at_height`, `tool::bull_nose_radius_at_height`); a ball at ap 0 gives 0. P22-0c-6b: a tapered ball clamps at the body's cutting cap on both doors (`CutBody::max_cut_diameter_mm` = `ToolBody::max_cut_diameter_mm`, the width at the flute top; `FeedsInput::cut_body`, filled by `CutBody::of_tool`; the shank is read by Step 4c only). Open: the V-bit hint adds the flat tip (P15 phase file). Sentry `one_d_eng_door_for_every_engagement_p15`.
- P20d: power = `[Ks A vf + F_edge Z n J] / 6e7` on the engaged section (`feeds::section`); the rectangle keeps its pre-P20d arithmetic, a V-bit reads the cone, a drill cycle the axial circle (advisory: no ladder, no pass 10, no envelope limit); P22-0c-6b D6: a tool with a body core cuts the ring, `A` and `J` x `k = 1 - (d_core / D)^2` (`CutBody::core_diameter_mm`; `k = 1` exactly with no core). `FeedsResult::power_kw` is `Option` (P18 3b): `None` = not modelled, never 0.0. Sentry `power_reads_the_true_engaged_section_p20d`.
- B6: one force line, `Material::force_line()`; power = line x grain factor, deflection = line. A refusal is `MaterialUnvalidated`.
- G6/G10: no drill rows; `DRILL_RULES` read the (Pocket, Roughing) side row x 1/Z. P20a: no drill RPM tier; the chart RPM ships through `clamp_rpm`, and the drill feed ceilings are the 3 mm Ramp Down per mm. Plunge = family fraction x the shipped feed BEFORE the radial lift (`PLUNGE_RULES`), re-run at the shipped feed and RPM. Ramp = `floor(min(feed, chip x rpm x Z / tan theta))`, feed also before the lift. P18 (D14): one door, `geometry::UnliftedFeed` (private field; `at_cut`, `FeedsResult::unlifted_feed`, the funnel's `unlifted_feed_at_kept_geometry`); `plunge::resolve_plunge_at` and `ramp::resolve_ramp_feed` take it; the raw `resolve_plunge` is for the FM1 column only. Sentry `the_plunge_reads_the_feed_before_the_lift_p18`. P20b: one vertical-rate limit, `vertical::VerticalRateLimit` (private fields, one constructor `new(ramp basis, machine)`): `min(candidate, G6 axial chip x rpm x Z, machine Z axis rate $112)`. Every plunge (`resolve_plunge`, all ops; Q8a is gone), the drill feed (Step 9c, the RPM follows down through `clamp_rpm`, `DrillFeedAtZAxisRate`) and the vertical part of a G6 ramp (`resolve_ramp_feed`, `RampArm::ZAxisRate`, the angle holds) go through `bound`. No kinematics: no Z cap, and the card says so. Sentry `one_vertical_rate_limit_for_plunge_drill_and_ramp_p20b`. The ramp angle and helix notes read the emitted radius (`helix_radius_for`). Suggest never writes the entry style (Q11).
- R4: the rubbing floor warns, never lifts. P16 (D8): it is the lower bound of power rung 4; no feed above it (or an edge term over the budget) ships the floor feed, never above the feed before the rung. Machine rigidity is `MachineProfile::rigidity`; every rigidity value takes `rigidity_basis(machine)`. `DEFLECTION_BACKOFF_TARGET_UM` is the one 200 um.
- P13c: the Pocket and Profile roughing depth is the force-budget depth; a Pocket-family width stops at `LimitKind::CornerCoverage`; a roughing proposal is the most removal per minute inside every limit; the Adaptive family keeps `adaptive_doc_factor`.
- Q1: at the feed cap Step 7 builds arm L (lower rpm, same chip) and arm S (same rpm, smaller chip) and ships by power (`CapArms`).
- G3/Q3/series: a chart with no operation gives (Pocket, Roughing) rows; `FAMILY_RULES` serve the 3D families; a flat finish reads its roughing row (`LutRoute::FlatAsRoughPocket`); a tie takes the lower printed chip; the series is a tie-breaker. P16 item 8: `LookupResult::band` (`VendorBand`, the rules in its doc) holds every matched printed row for the tool, size and material; Suggest ships the lowest chip, or the score winner when no member is at or below it (no rise); P23c: among the members a row printed at the tool's size outranks a lower size claim (`BandRule::ExactSize`), and the SpeTool 2D/3D tapered chart serves the 3D finish families (a fourth `FAMILY_RULES` row; sentry `an_exact_size_row_outranks_an_interpolated_member_p23c`); a hobby source (`SourceClass::HobbyFeedChart`, read from `source_manifest.json`) never enters; surfaces read `FeedsResult::vendor_band()`. P18 (D16) rule 1b: the query's tool family first; another family joins only when no query-family row passes the size rule, and `VendorBand::cross_family` names it on the card. `industrial_only/` rows are a baseline, not a lookup.
- S11: no raw fallback; `Unbacked` gives no feeds. `StockContext::stock_z` is `None` for a flat stock; `apply_stock_defaults` writes no Pocket or Adaptive 2D floor. One claimed band (`LookupResult::size_basis`). A printed value is a point. FC0: a printed IPM cell bounds its chip band.
- P21c: `ConstantChip { rpm_ceiling }` holds the chip and raises the RPM to the first named limit (`RpmLimit`: spindle max, `op_cutting_ceiling(feed_max_rate)` over the chip per rev, the Z rate on a drill, `power_at_rpm`, the operator ceiling or else the chart RPM, the vendor `rpm_max`); the ceiling, the spindle max and the vendor max always bind (a chart RPM above one comes down), the others only stop the rise; no multiplier, tier or headroom. The add door (`op_draft::suggest_for`) reads the project policy. A row with no printed RPM takes the lowest limit (no SFM RPM); `MatchChart` keeps the SFM RPM. `constant_chip_gap` is the one refusal rule (`FeedsError::ConstantChipUnstated`: no axis rates, no per-axis accelerations, or an empty ceiling on a row with no RPM), at `validate_tool_for_operation`; generation and export still run. Step 7 and Step 9c read the same op ceiling (Q11; `FeedsInput::feed_max_rate` is `None` at every product door today). Acceleration is a report (`machine::kinematics::reached_feed_share`, A3), not a cap. F201: `formula_constants()` marks each constant `Cited` or `Unsourced`; the Unsourced count is pinned (142 since P21c).
