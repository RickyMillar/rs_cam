# `compute/` — dispatch, catalogue, configuration, simulation

The operation registry and its dispatch, the configuration types, the guards, and the simulation orchestration. History: `git log` and the planning package each tag names (W*, K*, P*, S*).

## Files
- Dispatch: `execute.rs` + `execute/` — `execute_operation_annotated`; `prologue.rs` (the checks before an adapter), `findings.rs`, `standing_material.rs`, `shared.rs` (`link_ceiling_for`), the runners `layered.rs`, `territory.rs`, `height_field.rs`, `composed.rs`, `volumetric.rs` + `rough_3d.rs`, `curve.rs`; the family adapters `clearing_2d.rs`, `curve_engrave.rs`, `drilling.rs`, `bore.rs`, `finish_3d.rs`, `finish_raster.rs`, `project_curve_chaining.rs`; `dressup_apply.rs` (the dressup pipeline).
- Catalogue: `catalog.rs` (the registry) + `catalog/` (`capabilities.rs`, `cut_spec.rs` K1, `cuts.rs` (P29-3: `OperationConfig::cuts`, `CutList`, `DeclaredCut`; the one filler of `limits::CutFacts`; P29-7 7b: each generated cut (not the tab re-plunge, `U-TabReplunge`; one capped-step source per op) with its feed rule `DeclaredFeed::of_kind` and its `Presence`, a `MayOccur` cut names its `EXEMPTIONS` row; `CutList::dropped` names a cut over `MAX_DECLARED_CUTS`; P29-7 7c: `CutList::full_feed_width`, the one lift width; `feeds::planned` reads every cut), `entry_contract.rs` K4, `registry.rs`, `schema.rs`); `operation_configs.rs`, `config.rs` (`height_order`, THE plane-order rule; `DressupConfig`), `stock_config.rs` (`StockConfigPatch`), `tool_config.rs` (`ToolParamKey`, the private tool facts), `tool_fact.rs` (K3 `ToolFact`), `cutter.rs` (`build_cutter`), `transform.rs` (the frame doors, typed `Pt<..>`), `floor.rs`, `not_set.rs` (S11), `fixture_values.rs` (`test-support` only), `geometry_default.rs` (D8 tool rules), `domain.rs` (W6b), `stock_domain.rs`.
- Guards and item rules: `model_gouge.rs` (UX-7b), `feasibility.rs` (K5 `physical_rules!`), `edge_clear.rs` (`clear_edge_walls`), `open_sides.rs` (`grow_past_open_sides`), `obstacle.rs` (K1), `shoe.rs` (H1), `generated_empty.rs`, `validate.rs`.

## Invariants
- One simulation request, two builders (`ProjectSession::run_simulation`, the GUI). The shared decisions live in `simulate.rs` (`PhantomPriorStockScan`, `entry_tool_fields`, `group_stock_cut_direction`, `entry_metrics_not_applicable`, `group_stock_changes`, `group_obstacles`, `entry_head_fit`, `non_centre_cutting_warning_rows` / `core_contact`, `flute_reach`, `envelope_placement`; P22-0c-3: a contact row states its position in the G-code frame, `ContactFrame`); add the next one there, not in one builder. Both builders carve every enabled result, an empty one too.
- The tool owns its core (`tool::body::CoreZone`, from the `ToolBody` that `build_cutter` builds; feasibility reads `FeasibilityInputs::body`: the core and, P22-0c-6, the reach spans); the prefix key hashes `ToolBody::digest` (D1); `JobPhases::run_stages` records a plunge as a warning (K6, Q6).
- A new operation = a registry row + a config variant that derives `OpParams` (W5: the `#[param]` attributes are the schema). A published number states a bound, `frame_dependent` or `unbounded = "<reason>"` (F185). `domain::validate_operation` runs at add, op change, the setter and load (W6b). The row's `generate` is the dispatch; add no second path.
- The prologue runs first: cancel, `OperationConfig::not_set_for_tool` (depth, geometry, tool fact, feeds), the `GeometryRequirement`, `tool_cannot_compute` (only the V-bit ops refuse a wrong tool kind; every other tool refusal warns), the buried-face rule. It runs `selection::op_items` and gives `Prepared::{regions, curves, holes, hole_spans, region_ladders}`; an adapter reads `Prepared` and does not check again. No op closes an open path with a chord.
- A consumer reads `OperationConfig::capabilities()`, never a `match` on the op type (W2.4). `cut_rule` (K1) and `entry` (K4 `EntryContract`, the one entry source) are row fields with no `Default`; `OperationConfig::cut_spec()` builds the cut.
- Runners own the shared stages: Layered (`run_layered`: ladder, rest rule, one prepare per region, cancel per level, link, spans), Height-field (`run_height_field`: refuse, query, the one link stage), Composed (`run_composed`), Volumetric (`run_volumetric`), Curve (`run_curve`). An adapter reads XY, mask and stock from `Prepared::territory()`; a report reaches `GenerationFindings` only through `ctx.record`.
- Floor: the floor ops hold one `floor: Floor` (S11 default `Unset` refuses); `Floor::domain` is the one domain; `OperationConfig::set_floor` is the writer; `cutting_levels` steps `ops::depth::floor_ladder`. An empty ladder refuses. Per-area and per-hole floors come from `floor::region_floors` and `floor::hole_floors`.
- Rest rule = `Capabilities::rest_use` (`LevelClip`, `LevelSkip`, `ContourFilter` runner-owned, `StockColumn`, `LevelMask`). Session stages run after generation, not in op shapes (`attach_generic_rest_analysis`, `clip_and_split_entries`: one call each).
- A dressup's parameters live inside its `Option` on `DressupConfig`; `DressupKey` names every dressup. A helix radius is `helix_radius_for`; an entry feed is `entry_feed_rate()`.
- Geometry defaults (D8): no default without a tool; `geometry_default::write_rule_values` is THE writer (add door `Keep::Nothing`, tool change `Keep::StatedValues`).
- K1: every op keeps the tool out of the setup's obstacles, boundary on or off. One `ObstacleSet::resolve` and one `ObstacleToolView` (`for_tool(&MountedBody)` reads the zones; `for_head` = the shoe solver) serve the step, `link_ceiling_for`, the territory, the simulation and `collision_check`. A reader skips a `MoveIntent::ObstacleClearance` move by its intent.
- The model-gouge guard (`Capabilities::model_gouge`) and the feasibility table run after `run_stages` in `execute_job`; export warns `safety.cuts_into_model` (K6: no finding refuses).
- G-SIMMEM: the loop holds the cut trace once, by `Arc`. S0: a Z-axis group starts from the last Z-axis group's final stock; S3 stock changes then apply.
- `execute/` denies `cast_possible_truncation` and `cast_sign_loss`: a count from a user length goes through `util::steps` (F195).
