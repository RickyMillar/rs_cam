# `limits/` — one limit name, one check record

Feeds contract P29-2, P29-3, P29-6 and P29-7 (`planning/feeds_contract_2026-11-03/phases/`). The gates read `CutGroup`, `ByGroup` and `scope` since P29-6 6d; the limits before the simulation read the same `scope` since P29-7 7c (`feeds::planned`).

- `check.rs` — `Check` (limit, value, bound, unit, side, margin, state, basis, binding, population), `CheckState` (`Within`, `Exceeds`, `NoNumber(NoNumberReason)` (10i: `NoStatedFeed`; P29-9 9b: `OnlyALowerBound`, a check at a lower bound inside its limit; 9c: `NoEarlierLeave`), `NotApplicable(Geometry)`), `BoundSide`, `basis_of_bound` (the join of `BoundSource` into `feeds::sourced::Basis`).
- `project.rs` — the projections of the old records: `of_criterion` (`CriterionStatus`), `of_envelope` (`SafeEnvelope` at a planned point), `of_judged_value`, `of_rpm_choice`. `row.rs` (P29-10) — `CheckRow`, THE display row (subject, check, caveats, exemption, tone, face, detail; - `scope.rs` (P29-6 6d, P29-7 7c) — `scope(LimitId, CutGroup)`: `Judged`, `NotJudged` (row id, clause) or `NotACutLimit(PlanReason)` (a closed list: `DepthOnly`, `PlanLevel`, `MachineOrRpm`, `DrillGate`). One match, no wildcard; one table for both sides: every gate asks it through `tool_load::groups::judge_by_group`, every limit before the simulation through `feeds::planned::judge_declared_cuts` (an edge solve through its ceiling-only form `lowest_ceiling`, P29-10). The vendor depth table and the rubbing floor are limits of each cut.
- `exemptions.rs` (P29-3 A) — `EXEMPTIONS`, the one list of every exemption from a limit. A scope read in product code carries a marker comment `EXEMPT` with its row ids; a row names the files of its markers.

## Invariants

1. No signature and no code of this folder names an operation type, an operation family or a pass role, and the folder imports nothing from `compute/` or `session/`. A limit sees the cut, the tool, the stock and the machine (P29 design 4.5). The sentry scans the folder.
2. Each mapping from an old list is a match that names every variant. A second argument that tells two limits of one old name is a typed value (`ChipSide`), never a bool.
3. `Geometry` is a closed list of geometry reasons. An exemption is `Physical(Geometry)`, `NeedsRuling` or `Ruled` (a quoted operator ruling); no fourth class. A limit that an operation skips by a scope decision is `NoNumber(NoBound)` or `NoNumber(NotJudgedHere)`, never `NotApplicable`.
4. A projection takes the state of the old record. It does not judge a second time: `of_criterion` reads `LoadState`, `of_envelope` reads the margins of `SafeEnvelope::placing_margins` (the fold of `place`).
5. `Basis::setting` and `Basis::gates_export` (`feeds/sourced.rs`) equal the methods of the `BoundSource` that `basis_of_bound` read; a `Derived` basis over a value that does not gate does not gate (P29-10: the envelope force budget, one tone with the gate).

## How to add a limit

1. Add a `LimitId` member. The compiler stops at three matches with no wildcard: `scope` (each `CutGroup` cell: `Judged`, `NotJudged` with its row and marker, or `NotACutLimit` with its reason), `feeds::planned::planned_limit_of` (its role on the plane: `DepthCeiling(CeilingEdge)`, `ValueCheck(ValueCheck)` or `NotACutLimit(reason)`) and `tool_load::groups::gate_of` (its gates, or none with a named exemption row).
2. Before the simulation: one `impl feeds::planned::PlannedLimit` (`judge` over one planned cut) and, for a new `CeilingEdge` or `ValueCheck` variant, one arm in each envelope match (the compiler asks: the edge builder, the pick edge, the exact solve, the rows). The envelope reads every role through one loop (`envelope::plane_roles`); the driver `judge_declared_cuts` asks `scope` and builds the `ByCut` record. No limit decides a scope or walks the cut list.
3. After the simulation: one `tool_load::MetricEvaluator` (`judge` over one group's samples), a variant of `groups::Gate`, and a field of `tool_load::verdict::GroupVerdicts` (built in `evaluate_population`). The sentry `every_limit_judges_every_declared_cut_p29_7` holds the three lists against each other.
