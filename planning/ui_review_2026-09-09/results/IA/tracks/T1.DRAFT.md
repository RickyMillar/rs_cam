## (2) Three current sequences

**A. Fresh input → setup → toolpath (static path).** New app boots in `Workspace::Toolpaths` with `Selection::None` and empty session (`state/mod.rs:113`). Inspector shows "Getting started" 5-step list because no models and no toolpaths (`properties/mod.rs:117`). Operator must realize Toolpaths panel's "+ Add" is disabled until geometry exists → go to **File ▸ Import** (always reachable) → model added, camera fits, selection becomes Model. There is no auto-switch to Setup; stock is unconfigured but the Toolpaths workspace is where they landed. To configure stock they must click the **Setup tab**, then the "Edit stock dimensions" card (`setup_panel.rs:37`). Stock default dims come from model bbox on import (`controller/io.rs:25`). Add a tool via Toolpaths ▸ Tool Library (collapsed) ▸ "+ Add Tool" (`toolpath_panel.rs:210`). Add toolpath via "+ Add" → `Select(Setup)` then `AddToolpath` → selection becomes new toolpath (`events/toolpath.rs:175`). **Observed human interaction (expert walkthrough, untested novice):** a novice landing on Toolpaths with an empty panel has no visible "import model" affordance in the workspace itself — the only path is the File menu. The empty-state text in the inspector lists "1. Import a model (File > Import)" but the inspector is the *right* panel, which on the Toolpaths workspace shows operation properties for `Selection::None` = the same Getting Started list only when models AND toolpaths both empty; once a model is imported it collapses to "Select an item in the project tree" (`properties/mod.rs:140`), losing the step list.

**B. Switching model/setup/operation context.** Selecting Setup 2 from the Setup panel → `Select(Setup(id))` → `active_setup_index()` returns that index → GPU upload keys fixtures/keep-outs/datum to that setup's local frame (`gpu_upload.rs:606`, `state/mod.rs:132`). The viewport re-renders with that setup's orientation; `OverlayUploadKey.workspace` ensures fixture buffer swaps on workspace change (`app.rs:1084`). Switching to Toolpaths workspace: selection **survives** (no clearing in `switch_workspace`); if a Setup was selected, the Toolpaths inspector shows the toolpath panel only if selection is `Toolpath` — a `Setup` selection in Toolpaths workspace falls to the `Selection::Setup` arm showing setup properties, but the **left panel is the operation queue**, so the inspector and left panel now disagree on context. Selecting a toolpath → `pending_upload=true` (`events/model.rs:46`) so height-plane/rest-heatmap overlays refresh. Toolpath's owning setup determines the display frame even from Toolpaths workspace.

**C. Returning from simulation to edit then back.** In Simulation, `Esc` → `SwitchWorkspace(Toolpaths)` (`input.rs:245`). Selection is untouched, so the previously-selected toolpath remains selected and its properties panel is immediately editable. Returning to Simulation: click the Simulation tab → `switch_workspace` applies Simulation overlay defaults (e.g., stock viz mode) via `apply_workspace_defaults` which saves/displaces only the rows the target workspace names (`registry.rs:1376`); operator-set overlays not named by Simulation survive. Playback state (`current_move`, `playing`) persists across the round-trip — there is no reset on workspace switch. If simulation is stale (params changed in Toolpaths), the badge shows "stale" (`workspace_bar.rs:156`) and the timeline's `FreshnessGate` dims readouts (`readiness_panel.rs:53`). There is no "stale → re-run" affordance on the timeline itself; operator must use the left-panel Run button or the Simulation menu.

## (3) Structural navigation/IA problems (≤4)

**N1. Default workspace is Toolpaths, but the first task is always importing a model and configuring stock — both Setup-scoped.** `AppState::new()` sets `Workspace::Toolpaths` (`state/mod.rs:113`). The Toolpaths left panel offers no import affordance and no stock entry; the inspector's Getting-Started list vanishes the moment a model exists. **Remains after bug fixes:** yes — this is pure IA, not a wiring defect. A novice's first visible surface has no path to the first task except the File menu, which is unscoped.

**N2. The inspector (right panel) is workspace-blind — it dispatches purely on `Selection`, so a `Setup` selection in the Toolpaths workspace renders setup properties beside an operation queue.** `properties/mod.rs:108` matches `state.workspace == Simulation` for the sim panel, but Setup/Toolpaths/Readiness all share the same `match selection` body. The left panel changes per workspace but the right panel does not, so the two panels can describe different objects. **Remains after bug fixes:** yes. This is a structural mismatch between left-panel scope and right-panel scope, independent of any compute defect.

**N3. "Readiness" is reachable only via the workspace tab, not the Workspace menu, and is absent from the Simulation/Setup keyboard shortcuts.** The Workspace menu lists Setup/Toolpaths/Simulation only (`menu_bar.rs:155-171`); `Space` jumps to Simulation (`input.rs:165`); there is no keyboard route to Readiness. The Readiness tab is the export-readiness dashboard but nothing in the menu structure names it as a destination. **Remains after bug fixes:** yes — IA omission. (Minor: the menu and the tab bar are two declarations of the same four workspaces that can drift, and already have — Readiness is missing from the menu.)

**N4. Empty-state guidance is shown only at the project-wide empty state; partial states lose the route list.** Once any model exists, `properties/mod.rs:140` collapses to "Select an item in the project tree", and the Setup-panel Models section is collapsed by default (`setup_panel.rs:98`). There is no per-workspace "what to do next" — e.g., Toolpaths workspace with no tools shows "No tools defined" in a collapsed header; with no toolpaths shows "No toolpaths" italic. The next action (add tool, add toolpath) is discoverable but not sequenced. **Remains after bug fixes:** yes. This is a guidance gap, not a correctness one.

## (4) Proposed minimal flow/structure

**Proposed (current → minimal change):**
- **P1.** Add Readiness to the Workspace menu (`menu_bar.rs`) so all four tabs have a menu route. Effort: copy/local.
- **P2.** Boot into **Setup** when the session is empty (`state/mod.rs:113`: gate default on `session.models().is_empty() && list_setups().len()==1`). The first visible surface then offers "Import" in the File menu and the Stock/Machine/Models cards directly. When a job is opened, keep the persisted/current workspace. Effort: interaction/wiring.
- **P3.** Make the right-panel inspector **workspace-aware** for non-matching selections: when in Toolpaths and `Selection` is `Setup/Fixture/KeepOut/Stock/Machine`, show a short "Switch to Setup to edit this" panel with a one-click `SwitchWorkspace(Setup)` button instead of the full setup properties. Mirror for Simulation. Keep the current direct-edit behavior when the selection matches the workspace. Effort: interaction/wiring.
- **P4.** Replace the single empty-state branch with a small **per-workspace "next step" hint line** at the top of each left panel (Setup: "Import a model, then set stock"; Toolpaths: "Add a tool, then add an operation"; Simulation: "Run simulation to verify"; Readiness: "Resolve issues, then export"). Cheap labels, not a wizard.

**Alternative (heavier):** A single persistent left-rail project tree (Setups ▸ Models ▸ Tools ▸ Toolpaths) across all workspaces, with the right panel the only thing that changes. Resolves N2 by making left/right both selection-driven. Cost: reworks the existing per-workspace left panels (Setup cards, Toolpath queue, Sim op list) which each carry workspace-specific controls (drag-reorder, badges, run button). The brief warns against one giant tree without task evidence; I do not have task evidence that the per-workspace left panels fail, so I rank this below P1-P4.

**Power-user affordances to keep:** `Ctrl+Alt+E` direct-export skip (`menu_bar.rs:39`); `G`/`Shift+G` generate (`input.rs:155`); `Space`-to-Simulation (`input.rs:165`); `Esc`-to-Toolpaths from Simulation (`input.rs:245`); `1-4` view presets; `O` overlay panel and `S/P/R/X` overlay toggles (`input.rs:208`); drag-reorder toolpaths across setups (`toolpath_panel.rs:147`); viewport picking of fixtures/keep-outs/faces/drill targets (`viewport.rs:131`); modal exclusivity sparing a running Optimize (`state/mod.rs:174`); MCP `set_ui_view` as an alternate launcher.
