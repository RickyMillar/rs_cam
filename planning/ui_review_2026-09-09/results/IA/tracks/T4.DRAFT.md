## 2. Three current sequences

**(A) Manual chain → planner proposal → manual revision.** Operator builds a coarse+fine pair by hand in the Toolpaths workspace (3D ops default `boundary_inherit:true`, `FromRemainingStock` set manually). Opens **Plan multi-tool finishing** (`menu_bar.rs:181`); setup is silently the selected toolpath's setup (`planner.rs:318-331`). Ticks the same two tools, sets coarseness/overlap; **Preview** runs the drop-cutter walk on the Optimize lane (`planner.rs:188-243`), overlay paints tiers. **Apply plan** removes any prior `planner_origin` ops and emits fresh tiers `PEND`/`FromRemainingStock` (r05 §7). To revise the ladder the operator re-opens the dialog (ticks/dials restored, `planner.rs:153-187`), but **hand-edits to an emitted tier do not survive**: re-apply deletes by `planner_origin` (r05 §7). The only revision that persists is a **Duplicate** of a tier, which escapes ownership (`planner_origin:None`, r05 §7).

**(B) Diagnose → optimize candidate → apply.** Operator runs a sim, opens sim_diagnostics, focuses a hotspot and clicks **"Optimize this op"** (`sim_diagnostics.rs:265`). `open_optimize_modal` clones the cut trace and lends the session to the Optimize lane (`events/mod.rs:446-518`); modal opens `Loading`. Outcome lands `Ready`; a `FreshnessGate` banners if the baseline sim is now stale (`optimize_modal.rs:39,51-54`). Ranked/MarginalSafe rows show `Apply ⭐`; click routes through `apply_optimize_candidate` → `apply_toolpath_param_snapshot` + optimizer provenance stamp (`events/mod.rs:519-609`); modal closes, toolpath marked `stale_since`, auto-regen fires. For project scope the operator uses **Optimize project** rollup, checks "Apply now" rows, **Apply selected** → `Reconciling` → `Reconciled` with per-row `xtp` cross-TP mismatch flags (`events/mod.rs:1170-1265`; `optimize_project.rs:draw_reconciled`).

**(C) Project → export settings → artifact handoff.** Operator opens **Export Wizard** (Ctrl+Shift+E); resumes at `last_step_visited` (`input.rs:140-148`). Steps 1-4 set post/layout/units/tool-change on `session.wizard()` (each setter `mark_edited`, `input.rs:156-224`); step 5 re-emits gcode and runs the validator inline (`export_wizard.rs:step_preview`); step 6 shows a save summary with cycle-time basis caveat and **Save…** (`export_wizard.rs:step_save`). `WizardSave` → `handle_wizard_save` re-emits, re-gates, writes file(s), closes wizard (`app/export.rs:21-100`). The direct path (Ctrl+Alt+E) skips the wizard: `ExportGcode` → `show_preflight` (`input.rs:132`); the preflight gate shows readiness checks + tool-load overrides, then **Export G-code/Export Anyway** → `export_gcode_with_summary` (`app/export.rs:294`), a file dialog, no inline gcode preview.

## 3. Structural workflow problems (after correctness/cache/dead-control fixes)

**P1 — Destructive replacement has no pre-flight of what will be lost.** Planner Apply silently deletes every `planner_origin` op in the target setup (r05 §7); the only notice is the post-hoc toast suffix `"(replaced N prior planner op(s))"` (`planner.rs:213-228`). No dialog surface lists the names/count of ops to be replaced before the click, nor flags hand-edits that will vanish. Optimize-project Apply mutates multiple toolpaths at once with a checkbox column and one "Apply selected" — no per-row diff preview of the numeric change before commit (`optimize_project.rs:draw_apply_now_row` only shows Δ and −cycle). Even with the stale-cache and `planner_origin`-not-shown bugs fixed, an operator hand-tuning a tier has no on-dialog warning that re-apply erases it. **CODE** traced: `planner.rs:213-228`, `optimize_project.rs:478-528`.

**P2 — One setup, two numberings, no in-dialog picker.** The dialog header prints 0-based `setup #{setup_index}` (`multitool_planner.rs:97`); the tier overlay prints 1-based `setup 1` (r05 §7 / `registry.rs:836-839`). The setup is derived from the selected toolpath, not chosen in the dialog (`planner.rs:318-331`), and the active-setup rule differs (`AppState::active_setup_index` also honours selected Setup/Fixture/KeepOut, r05 §7). With a toolpath in another setup selected, Apply lands in the wrong setup with no in-dialog control to correct it. Not a cache bug; a scope-control gap. **CODE** traced: `multitool_planner.rs:95-99`, `planner.rs:318-331`.

**P3 — Temporary previews vs persistent settings share one "open a modal, set dials" shape but diverge in lifecycle and Close semantics.** Planner dials are ephemeral (kept on Close for re-open, gone on app restart — r08 §4 lists no `multitool_planner` persistence). Optimize outcomes are ephemeral cached state. Export-wizard setters call `mark_edited` and aim to persist (`input.rs:156-224`) — but r08 §4's `ProjectFile` inventory lists no wizard-overrides section (only setups/post/machine are serialized there; pause_message is on setups and IS persisted, `input.rs:194-203`). So three features that look identical to operate have three different "what does Close keep vs discard" answers, and the wizard's persistence of wcs/units/safe-z/dry-run/warmup/tool-change/layout/template is **needs-verify**. The operator has no consistent signal which dials are temporary and which survive a save. **CODE** (lifecycle divergence) traced: `planner.rs:240-262`, `events/mod.rs:277-281`, `input.rs:156-224`; **HYP** on wizard serialization gaps.

**P4 — Three export entry points, two gate orders, one shortcut that changes the gate.** Wizard (Ctrl+Shift+E) gives 7 steps with an inline gcode preview + validator gate (`export_wizard.rs:step_preview/step_save`). Preflight (Ctrl+Alt+E, or readiness "Export G-code…") gives readiness checks + tool-load overrides, then a file dialog with **no** inline gcode preview (`preflight.rs`; `app/export.rs:294`). Both ultimately emit through `io::export` but the operator sees a different number of decision screens and a different gate depending on entry; the power-user shortcut (Ctrl+Alt+E) is the one that skips the validator preview. Not a bug — a workflow-consequence: the expert fast path drops the only screen that shows emitted gcode before it is written. **CODE** traced: `menu_bar.rs:22,27,91,99`, `input.rs:132-140`, `export_wizard.rs:step_preview`, `preflight.rs`.

## 4. Proposed cross-feature contract

Distinguish four scopes and give each a consistent lifecycle + visible label:

- **Temporary preview** (tier overlay, optimize outcome, wizard step-5 gcode): owned by modal/overlay state, never persisted, **Close discards**, re-open rebuilds. Label: "preview — not saved".
- **Persistent project setting** (wizard layout/template/units/wcs/safe-z/tool-change/dry-run/warmup; post format; pause_message): owned by `session`, `mark_edited`, serialized. **Cancel keeps** on session for next export. Visible "saved with project" marker; verify the serializer actually writes each field (acceptance: reopen round-trips a non-default unit override).
- **Library snapshot** (tool/machine add-to-project): copy, new id, no back-ref. The catalog is a separate editable store from the project copy. Keep the two hover texts that state "snapshot — no live link" (r08 §6) and add the same on the project-side inspector ("copy of catalog X").
- **Destructive replacement** (planner Apply; optimize-project Apply): a **pre-flight diff** before commit — names/counts of ops to replace and a flag on hand-edited planner tiers — plus an explicit "this replaces, not merges" line in-dialog, not only in a post-hoc toast.

Expert shortcuts preserved: Ctrl+Alt+E direct export, Ctrl+Shift+E wizard, Review ▸ from rollup to per-op modal, planner re-open restoring dials, Generate All fixpoint, drag/Move-Up reorder, per-card Sim jump. None are removed; the contract makes their *scope* legible.
