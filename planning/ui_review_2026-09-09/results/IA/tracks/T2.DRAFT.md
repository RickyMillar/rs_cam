## (2) Three sequences

**First pocket.** Select Pocket → lands on Geometry tab (`mod.rs:3976` default), `Geometry` disclosure open because `result.is_none()` (`:3857`). Pick Tool + Input. The Pocket grid appears (`boundary_2d.rs:56`): Pattern, Stepover (⚡), Depth, DPP (⚡), Climb, Finishing Passes. To get safe numbers the user must leave this grid: the Stepover/DPP ⚡ write the **raw** `result.radial_width_mm`/`axial_depth_mm` (`value_row.rs:127-135`) with no clamp and stamp `✎ manual` at flush (`provenance.rs:190-217`). The funnelled path is on the Feeds & Speeds tab: `⚡⚡ Apply recommended speeds` + `⚡ Apply cut geometry` (`mod.rs:2077,2119`). Or `📊 Open Feeds & Speeds modal` (`:4660`) → compare → `⚡ Apply all`. No undo while the toolpath stays selected (`history.rs:184-199` flush-on-deselect).

**Choosing a finish quality level.** Pick UnifiedFinish → Geometry tab. The quality levers — `Scallop Height`, `Tolerance` — sit as bare DragValues in a flat grid beside `Stock to Leave`, `Raster Stepover`, `Z Step`, `Sampling`, `Monotone Cells` (`surface_3d.rs:870-960`). There is no quality frame: the user must already know scallop 0.01 mm ≈ fine cusp, 0.1 ≈ rough. The LUT feeds recommendation does **not** speak to scallop (it is geometry-driven), so no ⚡ help on the lever that matters most. `Stock to Leave` is the rough-to-finish contract but is unlabeled as such; the rough Pocket has no stock-to-leave field at all (`boundary_2d.rs:56-106`), so the handoff is invisible on the rough side. The only feedback on the resulting surface is post-sim deviation colour — not previewable from the form.

**Evaluate/apply a recommendation while preserving manual intent.** Inspector Feeds & Speeds tab: SPEED section shows editable Feed/Plunge with per-field ⚡ (coloured by **live recommendation** source) and a stored provenance badge (`mod.rs:1988-2042`); CUT section shows DOC/WOC read-only. User hand-set stepover=1.5 on Geometry (manual). Wants recommended feed, keep stepover. Two paths look equivalent but differ: (a) click `⚡` on Feed row → writes `round(result.feed,1.0)` **raw**, no `enforce_invariants`, no plunge≤feed check; provenance stamped `Manual` at flush. (b) `⚡⚡ Apply recommended speeds` → funnelled (`ApplyScope::Speeds`), keeps stepover, stamps `VendorLut`/`Formula` per field. The modal's CompareRow is read-only (no per-field apply since Checkpoint I-1, `compare.rs:92-101`); `⚡ Apply all` is `ApplyScope::Both` and would overwrite the manual stepover. So preserving manual intent *and* getting a funnelled, honestly-labelled feed requires path (b) — but path (a) is the visually tempting per-field affordance and it is the one that mislabels and bypasses clamps.

## (3) Structural design problems that remain after raw-value/cap fixes

**P1 — Recommendation provenance and saved-value provenance collapse on the Geometry tab.** Even with the raw-write bug fixed, accepting stepover/DPP via the ⚡ pill routes through `detect_manual_edits` (`provenance.rs:190-217`) and stamps `✎ manual` on a value the user took *from the recommendation*. RPM, stepover and DPP have provenance slots (`provenance.rs:113-126`) but **no badge renders them**: the CUT section is read-only labels and the Geometry `dv_pill` calls do not chain `.prov()` (`boundary_2d.rs:33-51`, `surface_3d.rs:68-69`). So the user cannot distinguish "I accepted a recommendation" from "I typed a number," and on three of five recommendable fields the label is invisible regardless. The Feeds tab Feed/Plunge rows do show the stored badge, but the ⚡ pill colour beside them is the **live** recommendation source (`mod.rs:2005`) — two colours on one row that can disagree, correct but needing the hover to decode (`value_row.rs:140-146`).

**P2 — No quality decision frame for finish ops; the rough-to-finish handoff is asymmetric.** Scallop/tolerance/stepover are the quality levers but are undifferentiated DragValues in a flat grid. There is no consequence readout ("→ cusp ≈ N µm"), no comparison to a target surface, and the LUT is silent on scallop. `Stock to Leave` exists on every finish op (`finishing.rs:*`, `surface_3d.rs:870-960`) but the rough Pocket has none (`boundary_2d.rs:56-106`), so the contract "rough leaves X, finish removes X" is only half-visible. The user must hold the handoff in their head across two operations on two tabs.

**P3 — The current/recommended/inherited/preview value roles are split across two surfaces with three apply semantics for the same field.** "Recommended DOC" appears as (i) a read-only label in the inspector CUT section, (ii) a `CompareRow` in the modal, (iii) a ⚡ pill on the Geometry tab — with raw, funnelled, and no-apply paths respectively. "Preview" lives only in the modal explore; "inherited" only in `PrecedenceField`. A user evaluating one recommendation must mentally merge three surfaces, and the per-field ⚡ (raw, mislabelled) sits next to `⚡⚡` (funnelled) using the same glyph family (`suggest.rs` `SuggestScope::Field` vs `Recipe` differ only by doubled glyph, `suggest.rs:42-60`).

**P4 — Flat 2-column grid for every form regardless of decision weight.** Adaptive3D puts ~18 fields — including safety-critical Entry Style (plunge into solid vs helix) — at equal visual weight with `Z Blend` (a smoothness toggle) and `Detect Flat` (`surface_3d.rs:54-250`). Drill's Cycle (which changes chip-evacuation safety) is a combo box at the same weight as Retract (R) (`drill.rs:97-115`). No form signals "decide this first." The `Geometry` wiring disclosure is the only hierarchy that exists, and it collapses once the op has a result (`mod.rs:3857`), hiding Tool/Input from a returning user.

## (4) Proposed primary/secondary/advanced hierarchy + value roles/apply semantics

Justification principle: a decision is **Primary** if it changes safety, the cut contract, or the quality target; **Secondary** if it tunes the primary within an already-chosen strategy; **Advanced** if it is geometry-recovery tuning most jobs never touch. Stock-to-leave is **not** blanket-Advanced: it is Primary on finish ops (the rough-handoff contract), Secondary on rough ops where it exists, N/A on drill.

**Pocket (simple rough).** Primary: Tool, Pattern, Depth, DPP, Stepover, `⚡ Apply cut geometry` (funnelled). Secondary: Climb, Finishing Passes, **Stock to Leave (add it)**, setup-context line. Advanced: Zigzag Angle.

**Adaptive3D (complex rough).** Primary: Strategy, Stepover/Optimal-load, DPP, Entry Style (+ conditional Ramp Angle/Helix Radius/Pitch), Stock-to-leave_axial. Secondary: Tolerance, Fine Stepdown, Mill Shallow + Shallow Angle. Advanced: Min Cut Radius, Detect Flat, Ordering, Z Blend.

**Drill.** Primary: Cycle, Depth, Feed Rate, Retract (R), Peck Depth (conditional). Secondary: Dwell Time, Retract Amt, target selector. Advanced: — (none; the selector is an action, not a param).

**UnifiedFinish.** Primary: Scallop Height (with `→ cusp ≈ N µm` readout), Stock to Leave (with `◀ rough left N` readout), Steep/Waterline Threshold. Secondary: Raster Stepover, Z Step, Tolerance, Overlap. Advanced: Sampling, Monotone Cells, Rest Reference/claims.

Value roles / apply semantics (current → proposed):
- **Current**: stored op value, editable. Keep. Render stored provenance badge on **all** recommendable fields (add `.prov()` to stepover/DPP/RPM rows), not just feed/plunge.
- **Recommended**: live LUT result. Currently read-only label (CUT) / raw ⚡ (Geometry) / CompareRow (modal). Proposal: show as faint `→ N mm` hint with source glyph beside the field; the ⚡ becomes a **funnelled per-field apply** (new field-grained `ApplyScope` through `apply_feeds_subset`), stamping `VendorLut`/`Formula`, not `Manual`. The hint's glyph is **recommendation provenance** (live source); the badge is **saved-value provenance** (stored source) — two distinct signals, two distinct types (already separate: `SuggestButton` vs `ProvenanceBadge`).
- **Inherited**: project default via `PrecedenceField`. Keep; extend pattern to any future project-default field.
- **Preview**: modal explore only. Keep modal-owned; the inspector owns apply. Label the inspector ⚡ explicitly "apply" (it writes), not "preview."
