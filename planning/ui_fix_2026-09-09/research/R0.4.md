# R0.4 — Issue → edit → recheck → return (IA D2)

Research document. Source-led at the working tree of 2026-09-09 (branch
`isoclip-rapid`, integration checkout). No code, config or test file was
changed. No cargo command was run. Every claim about current behaviour cites
a file and a symbol that was read. Claims not read are marked UNVERIFIED.

Consumers: PLAN §7 D2 (implementation), PLAN §5 P3 (MCP gap fill). Depends on
R0.1 for the freshness state names; this document uses the PLAN names
(current / edited-since / regenerating / waiting-on-upstream / error /
no-result / disabled) and marks each place where D2 reads them.

---

## 1. Question

An operator sees a finding in the Simulation workspace. They must:

1. locate it on the part and in the timeline,
2. open the operation that caused it, on the tab that holds the responsible
   setting,
3. regenerate and re-simulate what their edit invalidated, and nothing more,
4. come back to the same finding in the fresh evidence, or learn that it is
   gone, moved, or no longer measurable.

Today they do this by memory. This document specifies the data (the
bookmark), the four events, the remap rule, the failure text, and the named
findings that replace "Must address: Annotation 15".

## 3. Options

### 3.1 The bookmark

| Option | Data | Survives regeneration of the same op? | Survives an upstream op changing length? | Failure modes |
|---|---|---|---|---|
| A. Global move index | `usize` | No. Move counts change on any edit. | No. `boundary.start_move` shifts for every later op. | Lands on an unrelated move with no warning. This is the D2 anti-pattern. |
| B. Op id + subject + spatial anchor | `ToolpathId`, finding id (`DiagnosticId` string or issue kind), `[f64;3]` worst position, radius | Yes. The part does not move when the path is regenerated. | Yes. Anchor is in world XYZ, independent of indices. | Two fresh instances inside the radius (pick nearest, then worst severity). None inside the radius (report Moved or Not observed). Findings with no position (`WorstEvidence::default()` = origin, e.g. holder collisions from `holder_collisions` carry `[0,0,0]`). |
| C. Op id + subject + region/span id | `ToolpathId`, finding id, `(RegionSpanRole, region_id)` from `SpanPayload::Region`, or `semantic_item_id` | Partly. `SpanId` is the index into `AnnotatedToolpath.spans` and is rebuilt per generation, so the `SpanId` itself must never be stored. The payload `region_id` is stable for `RegionSpanRole::Node` (planner region table) and for `DrillHole`. For `GeneratorPass` it is the generator's own sequence number and can renumber. Whether `ToolpathSemanticItem.id` is stable across a regeneration is UNVERIFIED. | Yes. | Region missing after a boundary change or planner re-plan. Ambiguous for generator passes. |

Recommendation: B as the primary key, C as a confirmation and a tie-break, A never stored (a move index is computed at return time and thrown away).

### 3.2 The remap rule after regeneration

| Rule | Description | Failure mode |
|---|---|---|
| R1. Same index | reuse the stored move index | wrong place, silently (rejected) |
| R2. Same op, same subject, nearest anchor within radius | candidates = fresh findings on `toolpath_id` with the same subject; accept nearest to the anchor within `radius`; radius = `sim_triage::bucket_edge_mm(tool_diameter)` = `max(4 × D, 10 mm)` so one bucket is "a recognisable place on the part" at any tool size | none within radius → Moved / Not observed; several → nearest, then worst severity |
| R3. R2 plus comparability gate | before matching, check the fresh evidence is comparable: same `column_grid_cell_mm`, subject's metric `Measurable`, op included in the fresh run | not comparable → "cannot say", never "resolved" |
| R4. R3 plus region confirmation | if both old and fresh carry `(RegionSpanRole, region_id)` and they agree, prefer that candidate even if a nearer one exists | region payload missing (today `region_of` is `None`, so this arm is dormant until a resolver is wired) |

Recommendation: R3 now; R4 when the session supplies a `RegionResolver` (a follow-on to D2, not a blocker).

## 4. Recommendation

### 4.1 The bookmark struct and the typed focus

Store in `SimulationDebugState` (runtime only; not saved with the project). Replace the two untyped focus slots (`focused_hotspot`, `focused_issue_index`) with one typed focus so the card cannot mix index spaces (§2.3).

```rust
/// One finding the operator is working on. Never carries a move index.
pub struct FindingBookmark {
    /// The operation the finding is attributed to. `None` only for a
    /// project-scoped finding the boundaries could not attribute.
    pub toolpath_id: Option<ToolpathId>,
    pub subject: FindingSubject,
    /// World-frame XYZ of the worst instance, when the source has one.
    pub anchor: Option<[f64; 3]>,
    /// `sim_triage::bucket_edge_mm(tool_diameter)` at bookmark time.
    pub anchor_radius_mm: f64,
    /// `SpanPayload::Region` of the worst instance, when spans carry one.
    pub region: Option<(RegionSpanRole, u32)>,
    pub semantic_item_id: Option<u64>,
    /// Which evidence produced it. Read by the comparability gate.
    pub evidence: EvidenceStamp,
    /// Operator-facing name and one-sentence consequence, copied at
    /// bookmark time so the card can still show them after the finding
    /// is gone.
    pub name: String,
    pub consequence: String,
    /// Where `EditResponsibleOperation` should land (§4.3 table).
    pub edit_tab: Option<&'static str>,
    /// Result of the last `ReturnToFinding` remap; `None` until returned.
    pub remap: Option<RemapOutcome>,
}

pub enum FindingSubject {
    /// A triage or load-report finding, keyed by its stable rule id
    /// (`diagnostics::ids::*`, e.g. "project.plunge_class_load").
    Diagnostic(DiagnosticId),
    /// A safety event the GUI builds itself.
    RapidCollision,
    HolderCollision,
    /// A cut-trace hotspot (Class C advisory).
    CutHotspot,
}

pub struct EvidenceStamp {
    pub sim_generation: u64,       // SimulationRunMeta::sim_generation
    pub edit_counter: u64,         // SimulationRunMeta::last_sim_edit_counter
    pub column_grid_cell_mm: f64,  // SimulationResults::column_grid_cell_mm
    pub selected_toolpaths: Option<Vec<ToolpathId>>,
}

pub enum RemapOutcome {
    Matched { global_move: usize, distance_mm: f64 },
    Moved { global_move: usize, distance_mm: f64 },
    NotObserved,
    NotComparable(NotComparableReason),
}

pub enum NotComparableReason {
    NoFreshRun,                  // sim_generation unchanged
    OpNotInRun,                  // boundary for toolpath_id absent
    OpHasNoResult,               // R0.1: no-result / error / disabled
    CellChanged { from: f64, to: f64 },
    MetricNotMeasurable(SimMetric),
}
```

`SimulationDebugState` gains `pub focus: Option<FindingBookmark>` and a `return_armed: bool`. The old `focused_hotspot` and `focused_issue_index` go; the hotspot card becomes a `FindingSubject::CutHotspot` bookmark.

The anchor for each source:

| Subject | Anchor | Source field |
|---|---|---|
| Triage `Finding` (safety, actions, advisories) | `worst.position` | `sim_triage::WorstEvidence::position`; for `plunge_class_load` the diagnostic also carries `DiagnosticEvidence::Move { position }` |
| Rapid collision | `RapidCollision::start` | `SimulationChecks::rapid_collisions` |
| Holder collision | UNVERIFIED — `CollisionReport.collisions[i]` carries `move_idx` and `segment`; whether it carries a position was not read. If not, anchor from the move's `target` in `ToolpathResult::annotated.toolpath.moves` |
| Load-report `Exceeds` | none directly; `DiagnosticEvidence::SampleRange` gives `sample_start..sample_end` → `cut_trace.samples[i].position` | `ToolLoadReport::per_toolpath[].criteria()` |
| Cut hotspot | `representative_position` | `SimulationCutHotspot` |

### 4.2 The four events

Add to `AppEvent` (`crates/rs_cam_viz/src/ui/mod.rs`) and dispatch in `handle_internal_event`. All four are controller-level; none needs a pointer driver.

| Event | Payload | Handler responsibilities |
|---|---|---|
| `LocateFinding(FindingRef)` | `FindingRef { toolpath_id: Option<ToolpathId>, subject: FindingSubject, ordinal: usize }` — the row the operator clicked, resolved against the current named-findings list (§4.5) | 1. Resolve the row to a `FindingBookmark` (anchor, region, stamp from `last_run` and `results`). 2. Set `debug.focus`. 3. Pin `semantic_item_id` when present (`pin_semantic_item`). 4. Compute the global move once: triage `worst.move_index` is toolpath-local → `global_move_for_local`; collisions are already global. 5. Push `SimJumpToMove(global)`. 6. If `state.workspace != Simulation`, push `SwitchWorkspace(Simulation)` first. Do not touch `span_scope` (the lock stays the operator's). |
| `EditResponsibleOperation { toolpath_id: ToolpathId, tab: Option<String> }` | The op named on the card and the tab from the §4.3 table | 1. Refuse when `find_toolpath_config_by_id` fails: push a Warning notification "Responsible operation not known for this finding", change nothing. 2. `self.state.selection = Selection::Toolpath(id)` via `handle_select` (so `pending_upload` fires). 3. `self.state.gui.pending_toolpath_tab = Some((id, tab))` when `tab` is `Some` — the same one-shot slot the MCP uses, consumed at `ui/properties/mod.rs` `tab_override`. 4. `debug.return_armed = true` on the existing bookmark; do not clear it. 5. Push `SwitchWorkspace(Toolpaths)`. |
| `RecheckChanges` | none (scope is derived) | 1. Build `RecheckPlan` (pure function, also used by the card preview): `regenerate` = enabled toolpaths whose R0.1 state is edited-since or no-result, plus their rest-driven dependents (`StockSource::FromRemainingStock` downstream in the same setup, the predicate `gen_initial_stock` uses); `simulate` = `bookmark.evidence.selected_toolpaths` (else all enabled); `cell` = the pinned resolution, else `auto_resolution`. 2. For each id in `regenerate`: skip if `toolpath_rt[id].status == Computing` (the lane will supersede; do not double-submit), else `submit_toolpath_compute(id)`. 3. Store `pending_recheck = Some(RecheckPlan)`. 4. In the `ComputeMessage::Toolpath` landing arm (beside `pending_apply_resim`), remove the landed id; when the set is empty, `run_simulation_with_ids(&plan.simulate)` (or `_with_all`). 5. If `regenerate` is empty at step 1, run the simulation immediately. 6. When the plan needs a pinned cell and none is pinned (rest ops present), refuse with the same text `handle_generate_all` uses. Never launch Optimize. |
| `ReturnToFinding` | none | 1. Push `SwitchWorkspace(Simulation)`. 2. Run the remap (§4.4) against `results` + `last_run` + fresh triage/load report; write `bookmark.remap`. 3. `Matched`/`Moved` → `SimJumpToMove(global_move)`. 4. `NotObserved`/`NotComparable` → `SimJumpToMove(boundary.start_move)` for the op when its boundary exists, else leave playback where it is. 5. Clear `return_armed`. If `return_armed` is still true when a simulation lands (`ComputeMessage::Simulation` arm) and the workspace is Simulation, run steps 2–4 there so the operator does not click twice. |

`Esc` in Simulation keeps `SwitchWorkspace(Toolpaths)`. When a bookmark is focused and `return_armed` is false, D2 may make `Esc` emit `EditResponsibleOperation` instead; this is Open question 7, not part of the recommendation.

### 4.4 The exact "matching fresh evidence" rule and the failure text

Run in this order. Stop at the first failure.

| Step | Check | Outcome and shown text |
|---|---|---|
| 1 | `last_run.sim_generation > bookmark.evidence.sim_generation` | else `NotComparable(NoFreshRun)`: "No new simulation since this finding. Recheck to compare." |

| 6 | Candidates = fresh findings with the same `subject` on the same `toolpath_id`, from the same source list the bookmark came from (triage safety/actions/advisories, load report, GUI collisions). | none → `NotObserved`: "Not observed in the fresh run. | 7 | With an anchor: nearest candidate by 3D distance to `anchor`. Distance ≤ `anchor_radius_mm` → `Matched`: "Same finding, {d:.1} mm from where it was." Ties inside the radius break on higher `severity`, then on equal `region`. | Without an anchor (holder collisions carrying `[0,0,0]`, project-scoped rows): one candidate → `Matched` with text "Same finding (no position to compare)"; several → `Moved` to the first by severity rank, text "Several matching findings; showing the most severe." |

"Finding no longer observed" is therefore only ever printed after steps 1–5 pass. A `NotComparable` row keeps the old evidence inspectable: the card body shows the bookmarked name, consequence and anchor, dimmed, under the freshness qualifier from R0.1 (previous-run evidence).
