# F1.9 — G-EXPORTSKIP: export refuses an enabled operation with no result

Finding: R05 source track §5 (`planning/ui_review_2026-09-09/results/W03/support/r05_source_track.md`),
R0.1 §2.2 / §4.5 (`planning/ui_fix_2026-09-09/research/R0.1.md`).
Branch: `ui-fix/F1.9` from `ui-fix-2026-09-09`. Date: 2026-09-10.

## What was wrong

`io/export.rs::emitted_toolpaths` was a `filter_map` over the export
scope. An ENABLED toolpath with no result in either store
(`session.results` first, the `gui.toolpath_rt` fallback second)
returned `None`. The program was emitted without it, on every export
surface, and no surface said so. The pre-flight modal only read
"3/4 computed" as a Warning. The reachable case: a rest operation left
`AwaitingPriorStock` after a `generate_all` that ran out of rounds. The
operator reads "1 still waiting on upstream simulated stock", opens the
wizard, and saves a file that runs three operations for a project that
lists four.

Pre-fix reproduction (the sentry's first run, before the fix): with two
enabled toolpaths and only the first generated, every whole-project and
per-setup entry point returned `Ok` with a 13-line program, and the
file-writing caller wrote it to disk.

## The message table

One builder, `io::export::ungenerated_toolpath_message(name, status)`,
where `status` is the op's GUI runtime `ComputeStatus` (no runtime entry
reads as `Pending`).

| Runtime status | Text |
|---|---|
| `AwaitingPriorStock(_)` | `'{name}' is still waiting on upstream stock — run Generate All / simulate the prior operation` |
| `Error(err)` | `'{name}' failed to generate: {err}` |
| `Pending` / `Computing` / `Done` (no result) | `'{name}' is not generated` |
| `Disabled` (never stored; a disabled op is skipped, not listed) | `'{name}' is not generated` (unreachable arm, kept exhaustive) |

Surfaces and how each prints it:

| Surface | Shape |
|---|---|
| `export_gcode_from_session[_with_policy]`, `export_combined_gcode_from_session`, `export_setup_gcode_from_session[_with_policy]`, `export_single_toolpath_from_session` | `Err(VizError::Export(msg1; msg2; …))`, displayed as `Export failed: …` |
| Export wizard Preview / Save steps | already print the `Err` (`Cannot generate preview: …` / `Cannot prepare export: …`) |
| Pre-flight modal (`ui/preflight.rs`) | one `Fail` card per op: `Blocks export: {message}`; export buttons disabled |
| MCP `export_gcode` | `Export failed: {message}` (or `Export failed (setup 'X'): …` under `split_setups`) |
| Disabled toolpath | skipped everywhere, as before |

Behaviour change to know: the PerSetup wizard layout
(`app/export.rs::collect_setup_outputs`) skips a setup whose error
starts with `No computed`. A setup that holds an enabled ungenerated op
now returns the refusal instead, so that layout refuses too and names
the op. A setup with zero enabled toolpaths still reads `No computed
toolpaths in setup '…'` and is still skipped.
