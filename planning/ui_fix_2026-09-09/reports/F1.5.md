# F1.5 — G-BOUNDARYINHERIT: remove the dead inherit-boundary checkbox

Finding: UX-R03-009 (`planning/ui_review_2026-09-09/results/R03/REPORT.md`),
source-track lead X1. Branch `ui-fix/F1.5` from `58c1b55c`, worktree
`rs_cam_wt_b`. Date: 2026-09-10.

## What was wrong

The Geometry tab showed "Enable boundary / Inherit from stock" for every
3D op added on a mesh. No generation code read `boundary_inherit`:
`session/compute.rs` clones `tc.boundary` unconditionally, and no
stock-level default boundary exists. While ticked, the checkbox hid the
Source / Containment / Offset controls that drive generation. The operator
read "inherited from stock" while the finish was clipped to the model
silhouette.

## Compatibility choice

The core `ToolpathConfig::boundary_inherit` field and the core project
file (`session/project_file.rs`) are untouched. The core field has no
behavioural reader anywhere. The multitool planner sets it `false` and
two core tests assert that value as a provenance marker
(`multitool_plan_emission_o1`, `planned_tier_regions_boundary_o2`), so a
core removal is a separate, larger change and is out of this row's scope.
Removing it would touch about 100 initializers across core, CLI and
bench code.

GUI project file: the key is read and ignored, and never written. A file
that carries `boundary_inherit = true` or `false` loads and its
`[boundary]` table is unchanged. Sentry test
`legacy_boundary_inherit_key_loads_and_is_not_written`.

MCP wire: no tool emits or accepts a `boundary_inherit` key (`rg` over
`crates/` finds only Rust identifiers, no string literal). Nothing to
deprecate.

## "(auto)" provenance

Not distinguishable. The controller assigns `ModelSilhouette` on add for a
3D op on a mesh (`controller/events/toolpath.rs:138-152`), but nothing
stores that provenance, and the user can pick the same source by hand.
The panel prints "Boundary: model silhouette" without "(auto)" and passes
`auto = false`. The function keeps the `auto` parameter so a later
provenance flag can light it; the sentry pins both spellings.

## Sentry

`crates/rs_cam_viz/tests/boundary_controls_always_visible_g_boundaryinherit.rs`

1. `ui_sources_never_read_boundary_inherit`: reads every `.rs` file under
   `crates/rs_cam_viz/src/ui` at test time and fails on any line that
   names `boundary_inherit` other than a constant struct-literal write.
2. `summary_line_names_the_stored_source`: Stock / ModelSilhouette /
   FaceSelection / DerivedRestRegions, plus the `(auto)` suffix contract.
3. `legacy_boundary_inherit_key_loads_and_is_not_written`: a
   `ProjectToolpathSection` carrying `boundary_inherit = true` loads with
   its boundary fields intact and serializes without the key.

Pre-fix proof (test 1 against the unchanged sources, 22.3 s wall):

```text
the UI still reads the dead `boundary_inherit` dial (UX-R03-009):
.../crates/rs_cam_viz/src/ui/properties/operations/mod.rs:2408: boundary_inherit: true,
```

(The first pre-fix run flagged the constant write too; the allowance for
constant core writes was added after, and `mod.rs:3452` was the real

A fourth test that pushed a minimal `[[toolpaths]]` file through
`load_project` was written and dropped: the loader produced a default
boundary for a section with no tool, model or operation, which is loader
behaviour unrelated to this fix. The existing
`round_trip_persists_editable_2d_state` in `io/project.rs` covers the
full door with a non-default boundary.
