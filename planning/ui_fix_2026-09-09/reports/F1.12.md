## 1. What was wrong

Quitting with unsaved changes asked: an "Unsaved Changes" dialog with
Save / Discard / Cancel, raised from the OS close button and from
`AppEvent::Quit`.

**File › Open and Ctrl+O replaced the project just as completely and
asked nothing.** `open_job_from_path` installs a fresh `GuiState` and a
fresh `ProjectSession` and clears the undo history; every edit since the
last save was gone with one click, from a menu item sitting three rows
above Save.

MCP `load_project` went through the same `open_job_from_path` with the
same result, and an agent has no dialog to raise.

## 3. The three things the lead asked for

1. **The dialog is reused, not duplicated.** There is exactly one
   `egui::Window::new("Unsaved Changes")` in the crate, pinned by
   `there_is_exactly_one_unsaved_changes_dialog`. Only the verb
   ("Quit" / "Open…") and one consequence line differ between the two
   actions; the three answers are the same code.

2. **The MCP arm is a refusal that says what would be lost.** Two shapes,
   because two different things are at stake:
   - never saved → `Refused: the open project 'X' has never been saved, so
     everything in it would be lost -- 1 setups, 4 toolpaths, 2 tools.
     Loading would replace it and throw those changes away. Save it first
     (save_project), or pass discard_unsaved: true.`
   - saved before → `Refused: the open project 'X' has changes that are not
     in /path/to/job.toml. …`

   It deliberately does **not** quote a count of "changes":
   `GuiState::edit_counter` counts `mark_edited` calls — including the
   unconditional no-op pushes on navigate-away that R0.1 §2.2 item 4
   records — so a number there would mean nothing to the operator. Where a
   count IS the honest answer (nothing has ever been saved, so everything
   in the project is the loss) it is given.

3. **The camera fit is behind the guard, not in front of it.** F1.13 put
   `fit_camera_to_first_model()` on all three `open_job_from_path` routes.
   In the File › Open route that fit lived inside the arm, after the load.
   The arm now holds no picker, no load and no fit at all — they moved
   into `open_job_interactive`, which runs only after the guard is
   answered — so a Cancel moves nothing. `the_open_job_arm_holds_no_picker_load_or_camera_fit_of_its_own`
   pins this by asserting the three names are absent from the arm. The
   other two routes (`RS_CAM_JOB` at startup, MCP `load_project`) are
   unchanged in ordering; the MCP one gained a refusal that returns before
   the load, pinned by `the_mcp_refusal_is_decided_before_the_load`.

## 4. The sentries

`crates/rs_cam_viz/tests/open_guard_asks_before_discarding_g_openguard.rs`
(8 tests) plus one case in `controller/workflow_tests.rs`.

`RsCamApp` needs an `eframe::CreationContext`, so the dispatch arm and
the dialog cannot be driven from a test — the established pattern in this
crate (`mcp_toasts_report_outcome_g_mcptoast.rs` says so in its own header)
is to pin those by source and to drive the underlying decision against a
real object. That is what this file does: source pins for the arm and the
dialog, the real registered schema for the MCP contract, and
`controller/workflow_tests.rs::unsaved_project_summary_names_what_would_be_lost`
for the decision, through a real `AppController`.

## 6. What this task did NOT do

- **The other two load routes keep their behaviour.** `RS_CAM_JOB` at
  startup loads into a project that cannot yet be dirty, so it needs no
  guard. MCP `load_project` gained the refusal; it did not gain a dialog,
  because there is nobody to show one to.
- **No new dirty-flag sites.** What sets `dirty` is unchanged; this task
  only reads it.
- **The "N changes" question is left open.** Counting the actual
  difference between the in-memory project and the file on disk would be
  a better sentence than either shape here. It needs a diff the crate
  does not have, and inventing one from `edit_counter` would be a number
  that is wrong in a specific direction (too high). Recorded, not done.
- **No numeric threshold, gate bar, feeds constant or LUT row was
  touched.** No `Cargo.toml`, `.mcp.json` or permissions change.
