# F1.2 — G-PILLCLAMP: per-field ⚡ pills write the clamped value

Finding: UX-R03-014 (`planning/ui_review_2026-09-09/results/R03/REPORT.md`),
R04 source track §1 rows R3/R4 (`results/W03/support/r04_source_track.md`),
R0.5 §2.3 items 6–7 and §4.4 (`planning/ui_fix_2026-09-09/research/R0.5.md`).
Branch: `ui-fix/F1.2` from `ui-fix-2026-09-09` at `be4fa2e6`. Date: 2026-09-10.

## What was wrong

Every Apply button (Feeds tab, modal, batch, MCP `apply_feeds`) writes a
recommendation through `feeds::suggest::apply_feeds_subset`, which runs
`enforce_invariants` on a scratch clone and copies the clamped, rounded
values back. The 24 per-field ⚡ pills did not. `ValueRow::show`
(`ui/components/value_row.rs`) wrote `round_suggestion_value(s.recommended)`
straight into the field, and every producer handed it the raw `FeedsResult`
number (`r.axial_depth_mm`, `r.radial_width_mm`, `r.feed_rate_mm_min`,
`r.plunge_rate_mm_min`). On the demo pocket (Pocket, Ø6 two-flute flat end
mill, Generic Wood Router) the Depth/Pass pill wrote 4.2 mm where `⚡ Apply
cut geometry` wrote the rigidity-capped 1.2 mm, and the value was labelled as
the recommendation. Two follow-on defects rode with it:

- The pill's near-match test compared the configured value against the raw
  recommendation, so with configured 1.2 and raw 4.2 the pill stayed lit for
  a click that the funnel would have made a no-op (R0.5 §2.3 item 7).
- The pill wrote no provenance. At the frame flush `detect_manual_edits` saw
  the value move with the stamp unchanged and labelled it `Manual`.

## What changed

The pill now offers and writes the value the funnel would write for its one
field, and stamps the recommendation's provenance. The clamp chain is not
duplicated in the GUI. There is still no `ApplyScope::Field` arm
(Checkpoint I-1 stands): the core helper dry-runs `ApplyScope::Both` on a
scratch clone and reads one field back.

### Core (`rs_cam_core`)

- `crates/rs_cam_core/src/feeds/suggest.rs` — new `FieldApplyPreview`
  (`field`, `value`, `provenance`; `write_to` writes that one field and its
  stamp), `FieldApplyPreviews` (one slot per feeds field, `get(field)`),
  `preview_field_applies(op, result, tool, machine, material, pass_role, ctx)`
  (one funnel dry run, every field read back) and `preview_field_apply(…,
  field)` (one field). `ApplyScope`'s doc names the pill's route. No clamp
  constant, no funnel behaviour and no existing Apply route changed.
- `crates/rs_cam_core/src/feeds/provenance.rs` — `FeedsProvenance::get(field)`,
  the read counterpart of `set`.

### GUI (`rs_cam_viz`)

  `clamped: bool` and `calculator: Option<f64>`; derives `Clone`.

## The 24 pill sites

`Funnel` = the pill offers and writes the funnel's as-applied value with the
recommendation's stamp. `Raw (labelled)` = the funnel does not write this
dial on this operation; the pill offers the raw calculator value rounded to
the old grid, coloured by the chipload source, and its hover says "not
clamped"; a click takes no stamp and the flush labels it `Manual`, which is
true. The classification is pinned by `pill_site_classification_is_pinned`.

Note on 23/24: a drill's `feed_rate` IS its plunge (`DrillConfig::set_plunge_rate`
writes `feed_rate`). The funnel writes feed then plunge into the scratch, so
the value it leaves on `feed_rate` is the recommended **plunge** rate, clamped
to ≤ the recommended feed. The pill used to offer the lateral feed
(`feed_rate_mm_min`) for a Z-only cycle; it now offers what `⚡⚡ Apply
recommended speeds` writes. That is a value change on those two pills, in the
safe direction, and it is what the funnel has always written.

Near-match on every site now compares the configured value against the
as-applied value, so on the demo pocket (configured 1.2) the Depth/Pass pill
is greyed (R0.5 §5.4 D4 cross-reference).

## Sentry: `pill_writes_clamped_value_g_pillclamp.rs`

Six tests, core-level, on `ProjectSession::new_empty()` (Generic Wood Router,
default stock material) and `ToolConfig::new_default(EndMill)` with
`diameter = 6.0`:

- `depth_per_pass_pill_offers_the_funnel_value_not_the_calculator_value` —
  the acceptance: preview DOC bit-equal to `apply_cut_geometry_to_op`'s 1.2,
  not the raw 4.2; stamp equal to the apply's stamp.
- `the_fixture_still_shows_the_clamp` — raw ÷ funnel stays 3.50×, so the
  fixture keeps proving something.
- `every_field_the_funnel_writes_previews_exactly_what_it_writes` — 15
  operation families × 5 fields: a `Some` preview equals the `Both` apply's
  write bit-for-bit with the same stamp; a `None` preview means the funnel
  neither moved nor stamped the field. The test asserts at least 40 written
  (op, field) pairs were compared.
- `pill_site_classification_is_pinned` — the 24-row table above.
- `a_field_preview_write_moves_only_its_own_field` — `write_to` moves one
  field and one stamp.
- `previews_agree_with_both_scoped_applies` — speeds fields match
  `ApplyScope::Speeds`, geometry fields match `ApplyScope::CutGeometry`.

### Pre-fix failure

The first version of the file reproduced the pill's arithmetic locally
(`round_suggestion_value(result.axial_depth_mm, 0.001)`, what `value_row.rs`
wrote at HEAD) and asserted it equal to the funnel write. Run against the
unchanged source:


The funnel's 1.2000000000000002 is the clamp output, off the 0.001 grid.
That is why `ValueRow` now writes the preview verbatim instead of re-rounding.

## Not done, and things to know

- **Live click not verified.** No GUI tonight; the change is proven at the
  helper, the row component and the source-scan level. An MCP-VIEW pass on
  the pocket seed (hover text, greyed pill at 1.2) is the follow-up.
- **The same-stamp relabel hole exists on R1/R2 too, and was NOT touched.**
  `detect_manual_edits` labels a field `Manual` when its value moved and the
  entry's stamp equals the session's. `⚡⚡ Apply recommended speeds` and `⚡
  Apply cut geometry` stamp through `apply_suggested_subset`; when the new
  stamp equals the stored one (same vendor row, tool changed, value moved)
  the flush relabels their write `Manual`. The pill is protected by
  `pill_stamped_fields`; the two buttons could push the same list in two
  lines each, but that is outside this row and R0.5 §4.4 ("no change") so it
  is reported, not fixed.
- **`apply_contract_a3` cannot click the pill.** The harness renders no egui,
  so the new a3 tests pin the helper against the panel's apply and scan the
  sources for the raw `_sugg` pattern; the click → write path is covered by
  the `value_row.rs` verbatim-write scan plus the `pills.rs` unit test on
  `record_click` / `take_clicked`.
- **Per-frame cost.** The Geometry tab now runs `enforce_invariants` once per
  frame beside the calculator it already ran; the Feeds tab likewise. Both
  are a handful of clamps on one `OperationConfig` clone with
  `SuggestContext::default()` (the runtime back-off short-circuits without a
  model bbox). Not measured; no visible change expected.
- **Pass-9 dependent change is withheld, not shown.** R0.5 §4.3 note 3 asks
  the hover to say "Feed would also change under Apply all" when a
  single-field DOC write hides a feed move. `FieldApplyPreviews` carries the
  feed preview, so the data is there; the wording is D4's, not added here.
