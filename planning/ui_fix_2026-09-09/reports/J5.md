  for check/clippy"**.

There IS a real hardware constraint underneath, and it is worth stating
correctly because it explains why the wrong version was plausible:

- This machine carries **no swap at all** (`swapon --show` is empty) against
  54 GiB of RAM. Memory pressure is an immediate OOM kill, not a slowdown.
- An **uncapped** full heavy gate once killed the Claude Code process itself.
  The operator's words then were "whatever you just did is crashing this
  terminal". The fix adopted at the time was a cap —
  `CARGO_BUILD_JOBS=2`, `--test-threads=2`, detached — not a ban.

So the correct rule is: cap it, run it at a phase end, and hold the single
cargo lane. That is what I did.
