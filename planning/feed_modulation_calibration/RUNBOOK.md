# Feed Modulation Calibration Runbook (F-034 + F-036c)

**You'll run three G-code programs on the Shapeoko XXL and record wall-clock
elapsed time for each. The results feed two `#[ignore]`d cargo tests that
unflag once the numbers land.**

Two open findings close on the back of this bench session:

- **F-034** — calibration of the acceleration-aware cycle-time integrator.
  The model predicts elapsed time from the toolpath geometry + machine
  kinematics; we need one real-machine wall-clock to ground that prediction
  within ±15 %.
- **F-036c** — verification that per-segment adaptive feed modulation
  actually moves cycle time on a real toolpath. The brief's target is
  ≥ 20 % reduction; if your tuned baseline is already at the LUT band's
  upper end, modulation may instead *lower* feed for tool-life safety
  (see "Interpretation" below).

## Safety + setup

**You can run all three programs dry — spindle off, no stock, no tool
contact.** Wall-clock elapsed is the only signal we need; the planner's
accel/jerk behaviour is what's being measured, not material removal.

If you'd rather wet-run for a more realistic test, the
`f036c_wanaka_back_rough_*` pair cuts hardwood at ~3 mm depth-per-pass
across a ~14 × 15 cm terrain. The `f034_reference_wanaka_pin_drill.nc`
is a 6-hole peck-drill cycle into the same stock (6 holes, 25 mm deep).

**Pre-flight (any run):**

1. Confirm the Shapeoko XXL is on stock GRBL firmware
   (`$$` then `$130` / `$131` / `$132` returns accel ≈ 250 mm/s²,
   `$110` / `$111` / `$112` returns max feed ≈ 4000 mm/min). The F-034
   integrator's `MachineKinematics::shapeoko_xxl_stock()` preset uses
   those defaults — if you've raised accel via `$$=` edits, record the
   new values and tell me so I can update the preset before unflagging.
2. Home the machine (`$H`).
3. Pick a workspace origin that gives the toolpath full XY/Z clearance.
   Wanaka's stock is anchored at `(-20, -25, -20)` in part-Z; if you
   dry-run, set the workspace origin so X+ / Y+ travel of 150 mm /
   160 mm and Z+ travel of 30 mm above origin are all reachable.
4. **Use a stopwatch / phone timer**, not the Carbide Motion runtime
   display — the controller-side display can lag by tens of seconds on
   long programs.

## What to record (per run)

For each of the three programs:

```
Program: <filename>
Start time:   HH:MM:SS
End time:     HH:MM:SS
Elapsed:      MM:SS
Notes:        <anything unexpected — stalls, error pauses, controller buffer warnings>
```

If GRBL throws an alarm or buffer warning on the modulated program
(thousands of per-move F-words can over-fill the planner buffer on
small-RAM controllers), record the alarm code and the move index it
fired on. F-036's brief flagged this as a known risk:

> "Verify Shapeoko XXL (GRBL controller) parses per-move F-words
> correctly. Most modern GRBL builds handle this fine but the planner
> lookahead buffer can be undersized; if cycle time goes UP rather than
> down on the real machine, that's a controller-buffer issue and the
> F-036 pipeline needs a buffer-size advisory."

## Suggested order

1. **`f034_reference_wanaka_pin_drill.nc` × 3 runs.** Short — record
   each, then take the mean. This pins F-034's integrator before the
   longer programs.
2. **`f036c_wanaka_back_rough_modulation_off.nc` × 1 run.** ~13-20 min
   on a real machine. Establishes the unmodulated baseline.
3. **`f036c_wanaka_back_rough_modulation_on.nc` × 1 run.** Same length.
   This is the "did modulation help?" measurement.

Step (1) can happen at any point — the others are sequential.

## Interpretation guide — what the numbers mean

### F-034 (Pin Drill)

| Wall-clock vs. integrator prediction | Verdict |
|---|---|
| Within ±10 % | Tight calibration. Test asserts at ±15 % so headroom is fine. |
| ±10–25 % | Acceptable v1. Tighten in a future finding (jerk-limited junction model, arc-as-chord refinement). |
| > 25 % off | Something's wrong — likely the Shapeoko XXL accel/jerk defaults differ from `MachineKinematics::shapeoko_xxl_stock()`'s preset. Send me your `$$` dump and I'll recalibrate the preset. |

### F-036c (Back Rough off vs. on)

Three possible outcomes:

1. **`modulated < unmodulated` by 20–50 %** — the canonical Fusion-HSM
   adaptive-feed-control win. Wanaka's commanded feed was under the LUT
   band midpoint; modulation raises it on light-engagement segments.
   F-036c lands as the brief promised.

2. **`modulated ≈ unmodulated` (±5 %)** — wanaka's tuning was already
   close to the LUT band. Modulation is doing the right thing but the
   user-visible delta is small. F-036c still lands; we just adjust the
   finding's narrative.

3. **`modulated > unmodulated`** — wanaka was over-fed (above LUT band).
   Modulation lowers the feed for tool-life safety. Cycle time goes up
   but tool wear / surface finish should improve. This is the F-036
   algorithm's protective mode; not a win on cycle but a win on
   process robustness. Worth noting in F-036c's narrative + opening
   a follow-up finding for an opt-in "speed-priority" modulation mode
   that ignores the band ceiling.

The summary diagnostics already hint at outcome (3): the modulated
G-code has mean feed 1539 mm/min vs. unmodulated 3371 mm/min — wanaka
appears to have been tuned above the hardwood-roughing LUT band. The
bench measurement confirms whether that's the case at runtime, not
just by line count.
