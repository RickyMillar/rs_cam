## What changed in the runner

`crates/rs_cam_cli/src/smoke.rs` now intercepts any `stock_*` prefixed key
in a case's `baseline_params` and routes it to `session.stock_mut()`
instead of the toolpath operation schema. Implementation:

- New helper `apply_stock_overrides(session, baseline_params, case_id)`
  invoked once per case (after material override, before disabling
  existing toolpaths).
- `stock_top_z=N` → sets `stock.z = N - stock.origin_z`, then sets
  `stock.auto_from_model = false` to prevent re-derivation from
  undoing the override.
- The per-toolpath `set_toolpath_param` loop in
  `materialize_case_toolpath` now skips any key starting with
  `stock_` so they don't pollute `param_warnings` with "unknown
  parameter" noise.

Unknown stock_* keys are logged via `tracing::info!` and ignored —
add a new arm to `apply_stock_overrides` when more keys land.

## Why this is the right baseline

Round-09 (operator MCP run, recorded in
`planning/acceptance_loop/rounds/round-09-2026-05-25/STATE.md`)
measured AS013 deflection at ~105 µm Within when the stock was
configured to top at Z=30 via the project file. The CLI smoke runner
couldn't replicate this because `set_toolpath_param("stock_top_z", …)`
on a 3D Rough op is invalid — the parameter belongs to stock, not
operation. Step 5.1 makes the runner do what round-09 did manually.

The new 109.0 µm reading sits within 4 µm of round-09's 105 µm —
the residual delta is within the dexel-resolution noise band for
the terrain fixture.
