# P9: One engagement definition before and after the simulation

Status: NOT STARTED | Contracts: K7 (reads K1, K2b; writes K8) | Rulings: Q1, Q5, Q6 |
Numbers move: yes. Pre-sim power (the envelope maximum, not the nominal point), the post-sim

## Goal

One `Engagement { ap, psi, d_eng, section }` type, with one constructor from a planned cut
(`CutSpec`, K1) and one from a simulation sample (the arc). Every power and lateral-force reader
builds its inputs from it, so Suggest, the post-sim gate and the modulator read one width for one
cut (the operator rule "one load definition codebase-wide"). Pre-sim power evaluates a set of
cases (nominal, slot, planner cap) and ships the maximum with its case name. The simulation
places its measured engagement and power on the K2b envelope; a point outside is a warning that
names the limit. Suggest never reads the simulation (Q5).

## Preconditions

- Committed: P4 (K1 `CutSpec`, `FirstPass`, `Radial::Slot`), P5 (K2b `SafeEnvelope`, `Limit`,
  `LimitKind`), P5b (envelope plot, K8 lineage). Changes 1-2 land BEFORE P8 Q1 (lead decision);
  P8 then reads the set through `cap_arm_demand_kw`. Changes 3-4 may land after P8.
- Owned by the perf session: `compute/simulate.rs`. Read with `git show HEAD:<path>`.
- Decided (lead, 2026-11-03), D-W: the one width rule from an arc. Today the gate uses the
  arc-equivalent slab `(psi / pi) x 2 r_eng` (`tool_load/power.rs:271-273@40cf411a7`); Suggest
  and the modulator use the geometric `ae` with `cos psi = 1 - ae / r`
  (`feeds/force.rs:57@40cf411a7` `immersion_angle`). They agree at psi = pi/2 and pi and differ
  between (B 4.2). The sample constructor uses the geometric inverse `ae = r (1 - cos psi)`: it
  is the exact inverse of `immersion_angle`, and the shear term then equals the removed volume
  rate. The gate's slab retires; name the moved cells.

## Changes

   - What: `Engagement` in a new `feeds/engagement.rs` (core, below `feeds/` and `tool_load/`).
   - How:
     ```rust
     /// CONTRACT K7. Built only by `from_cut` and `from_sample`.
     pub struct Engagement { ap: f64, ae: f64, psi: f64, d_eng: f64, section_mm2: f64 }
     impl Engagement {
         pub fn from_cut(cut: &CutPoint, tool: &ToolGeometryHint, d_nominal: f64) -> Self;
         pub fn from_sample(s: &SimulationCutSample, tool: &ToolDefinition) -> Option<Self>;
         pub fn power_inputs(&self, line: ForceLine, rpm: f64, z: f64) -> PowerModelInputs;
     ```
