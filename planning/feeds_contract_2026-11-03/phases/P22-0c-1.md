## 1. Design as built

- `tool/body.rs` (new): `AxialSpan`, `SpanTop::{At, Open}`,
  `Zone::{Cutting, Contact}`, `CuttingZone`, `CuttingKind::Flutes`,
  `ContactZone`, `ContactRadius::{Mm, Shelf}`,
  `ContactKind::{Core, FluteTop, Shank, Holder, Shoe}`, `ToolBody`,
  `MountedBody`. No type has a `Default`. Every match names each variant.
- `ToolBody` has ONE constructor, `ToolBody::new` (`pub(crate)`). Only
  `ToolDefinition::new` and `ToolDefinition::with_non_centre_cutting` call
  it; `build_cutter` is the production door of both.
- `ToolBody::zones()` is THE zone table (design section 3): flutes `[0, L]`
  (inner = core radius or 0); core `[protrusion, L]`, `0..core_d/2` (only
  for `CentreCutting::No`); flute top `[L, L]` out to the envelope radius;
  shank `[L, stickout]`, `shank_d/2` (only when `stickout > L`).
- `ToolDefinition`: the fields `shank_diameter`, `stickout` and
  `non_centre_cutting` are gone. One private field `body: ToolBody`, and
  the accessors `body()`, `shank_diameter()`, `stickout()`.
  `MillingCutter::non_centre_cutting` reads `body.core_limits()`.
- `ToolDefinition::to_assembly(fit)` returns `MountedBody` (body plus the
  head bands). `MountedBody::assembly()` gives the old `ToolAssembly`
  view; every old caller reads that view in this phase.
  `MountedBody::zones()` gives the tool zones, then each head band as a
  contact zone (`SpanTop::Open`).
- `HeadBand` moved to `machine/head.rs`, with a machine-owned
  `HeadBandKind::{Holder, Shoe}` in place of `AssemblySegment`.
  `machine/` no longer imports `stock/`. `stock/collision.rs` has
  `From<HeadBandKind> for AssemblySegment`; `tool/body.rs` has
  `From<HeadBandKind> for ContactKind`.
- `with_non_centre_cutting(Option<NonCentreCuttingGeometry>)`: the stated
  core facts only (decision 3).
- D1: `hash_tool` hashes the shape probes as before, plus
  `ToolBody::digest`. The digest destructures every body fact (flute
  length, envelope radius, shank, stickout, core diameter, protrusion),
  `..`-free. It replaces the hand-written shank, stickout and core-limit
  entries. The key changes on every core fact, because the descent angle
  is a function of the two core facts.

## 4. Decisions

1. Typed private facts, not a stored `Vec<Zone>`: a stored list needs a
   search and an impossible "zone absent" arm in every view. The body
   stores the five facts; `zones()` derives the table; each view reads the
   same facts. The sentry holds every view equal to the table.
2. `MountedBody` keeps the head as `Vec<HeadBand>` (the machine's type)
   and gives `ContactZone`s through `zones()`. So no reverse map from
   `ContactKind` to a head band needs an impossible `Core`/`FluteTop` arm.
3. Lead ruling (2026-11-09) on question 3: `with_non_centre_cutting` takes
   only the stated facts, `Option<NonCentreCuttingGeometry>` (core
   diameter, protrusion). `NonCentreCuttingGeometry::limits` derives the
   descent angle in ONE place; no caller can pass an angle that disagrees.
   Callers changed: `build_cutter` (`non_centre_cutting_geometry()`) and the
   D1 test builder (its assertions are the same). Re-run after the change:
   the new sentry 2/2; g_centrecut, k5_centrecut, q8, f029, k6, the two
   g_simcore, `sim_prefix_memo_s5` 17/17: green; D1 test green; core
   `--lib` (three features) 2818 passed, 1 failed (the known timing red);
   full clippy clean; rustfmt clean on the changed files.
4. No drill case: `ToolType` has no drill (the drill check is analytic).
5. The `rg` guard of design section 4 (`centre_core_diameter_mm / 2`
   outside `tool/body.rs`) belongs to P22-0c-2, which deletes those sites.
