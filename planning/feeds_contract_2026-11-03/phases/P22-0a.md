## 1. Design

### 1.1 The rule

A tool with `non_centre_cutting` limits has a centre core of radius `c`
(`centre_core_diameter_mm / 2`) that removes no stock. Only the blade ring
`c <= r <= R` cuts, to the blade bottom (the tip). The core does not crush
wood (the report's recommendation, point 4).

### 1.2 Why a coverage rule and not a second height channel

The report proposes a second LUT channel (`h = +inf` for `r < c`) and a new
kernel per segment, and it turns the S2 air-skip off or bounds it. The code
shows a simpler correct way:

- The core changes WHICH cells a stamp cuts. It does not change the HEIGHT
  of the removal surface where the ring cuts: that stays `tip + h(r)` of the
  envelope (`h = 0` for a flat tool).
- Every stamp kernel already asks one coverage function per cell
  (`point_cell_coverage`, `segment_cell_coverage`). A blade-ring variant of
  each function returns the coverage of the ring sweep and the segment
  parameter where the ring cuts the cell. The kernels, the band dispatch,
  the swept dispatch and the playback route stay as they are; each call site
  selects the variant from the table (`RadialProfileLUT::blade_ring`).
- The ring removes a subset of what the envelope removes, at the same
  surface. So every bound that the air-skip, the tile mip and the
  sliver-safe channel (`conservative_top`) rest on stays true. The S2 skip
  stays on and exact; no new LUT channel is necessary.

### 1.3 The closed form for one straight segment

A cell centre `q` and a segment `p(t)`, `t` in `[0, 1]`. The distance
`|q - p(t)|` is a convex function of `t`, so its maximum on the segment is
at an end point.

- The ring cuts `q` exactly when the closest distance is `<= R` and the
  farther end point is at a distance `>= c`. (Proof: the distance is
  continuous; if the closest distance is below `c`, it reaches `c` on the
  way to the farther end point, and there it is `c <= R`.)
- The parameter: if the closest distance is `>= c`, the closest point is in
  the ring, and the kernel keeps `t_closest` (the same value as today). Else
  the ring crosses `q` at `t0 +- sqrt(c^2 - d_perp^2) / L` (`t0` the
  unclamped projection, `d_perp` the distance to the line). The kernel takes
  the deeper of the two that are in `[0, 1]`. The tip Z varies at most by
  the 0.02 mm sub-segment drop between the two, as for the closest point.
- A point stamp (a pure plunge) cuts the cells at `c <= r <= R` of the tip.
- Boundary cells use the same 4 x 4 sub-sample fan as the outer edge: a
  sub-sample counts when it meets both conditions.

### 1.4 Which LUT carries the ring

`RadialProfileLUT::from_cutter` stays the envelope (no ring). A new
constructor `RadialProfileLUT::for_stock_stamp` adds the ring from
`MillingCutter::non_centre_cutting`. Only the simulation builds its table
with it: the three `TriDexelStock::simulate_*` helpers that take a cutter
(`dexel_stock/simulation.rs`) and the session simulation
(`compute/simulate.rs`). The 3D adaptive planner stock, the dressup replay,
`feedopt` and the collision probe keep the envelope. Reason: those are
generation paths; a change there moves toolpaths (P22b owns the planner
side). See section 6, question 1.

## 4. Decisions

1. The core is a coverage rule, not a height channel (section 1.2). The S2
   air-skip, the tile mip and `conservative_top` stay on and exact, because
   the ring cuts a subset of the envelope cut at the same surface.
2. The ring is opt-in per table (`for_stock_stamp`); `from_cutter` is the
   envelope. Only the simulation reads the ring.
3. The core crushes no wood (report point 4). The stock keeps the post.
4. The engagement metrics of a sample (the midpoint-disc arc, the section)
   are not changed: they still count the core disc. P22-0b or later.
