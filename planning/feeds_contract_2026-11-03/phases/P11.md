# P11: the engagement force model, chip first, and limits that follow the feed

Status: NOT STARTED (card by the lead, 2026-11-04, from the operator discussion and
`research_ae/`) | Contracts: K2b, K7 | Numbers move: yes (feeds, the envelope, FM1)

## Goal

For flat end mills first (other shapes later): the chip load is held in its band, the feed is
sized for the actual chip (chip thinning), and force, power, deflection and tool strength at
that chip bound depth x stepover. The envelope then shows the depth-stepover trade, and a
higher feed (a thicker chip) pulls the force limits in.

## Operator statements (2026-11-04)

- "I know intuitively that a full slot is more load ... Otherwise we would just full slot all
  the time?" The model must make a slot cost more than a light stepover.
- "Maybe depth and stepover live in a more detailed combined model?" Yes: one
  engagement-angle force model with the helix (`research_ae/REPORT.md` summary item 3).
- "Should the flow be backwards? ... we don't want to change chipload much; a small chipload
  because of depth means we burn." Chip first (`research_ae/REPORT.md` section 6).
- "I was hoping that a high feed would bring those limits in (due to tool breaking)." Today
  the envelope is sized at the suggested chip, only the power line reads the feed, and no
  tool-strength (breakage) limit exists. The deflection target (200 um) is unsourced.
- "If we can prove that with chip thinning our calcs match the recommendations ... that model
  should intersect the recommendations everywhere." Validation first (step 0).

## Steps

0. **Validation study (needs the operator's go; asked 2026-11-04, not yet given).** A script
   runs the model (chip thinning + helix engagement force) against every row of
   `data/vendor_lut/observations/`, plus an HTML page with an assert script for each claim.
   Rules: no constant tuned per row; each constant from a repo source; any assumption about
   the vendor condition (e.g. "the chart assumes a slot") stated once for all rows; the pass
   rule written before the run (e.g. the model chip falls inside the printed band for N % of
   rows). A failure names the missing term. The lead's first check by hand: holding the force
   constant from 1 x D to 2 x D in a slot gives about an 80 % chip cut, where the vendors print
   25 %; the vendor depth steps are not constant force.
1. **Operator ruling on chip thinning against N-8** (`CHIPLOAD_LITERATURE_VERDICT.md`), with the
   step 0 result as the evidence. Garr's ">= 50 % stepover" rule is the offered source.
2. **Fix the envelope defects** (`research_ae/FINDINGS.md`):
   - D-A: the speeds grid sizes power at the capped depth, not the requested one.
   - D-B: the 42.75 mm deflection edge is the search bracket (0.95 x stickout), drawn as a limit.
3. **The engagement force model** (with P9's `Engagement`): force summed over the engaged
   edge with the helix wrap (`tool/mod.rs:250-255` already computes it); the one-tooth peak
   model overstates a deep narrow cut about 4x and a slot 1.16x.
4. **Chip first:** hold the chip in its band; size the feed for the actual peak chip; the vendor
   depth table (`doc_derating_scale`, Freud / Onsrud / Amana 1-2-3 x D) becomes a visible limit
   ("vendor ceiling at unknown width"), not a feed multiplier.
5. **Limits that follow the feed:** the envelope is sized at the operator's chip, so a higher
   chip moves the force and deflection limits in. Add a tool-strength limit (shank bending
   stress) if a printed source for the tool material strength exists; else Unsourced.
6. **Sources needed before a constant gates anything:** `SLOTTING_THRESHOLD`,
   `SLOTTING_DOC_CAP`, `adaptive_woc_factor` (the "20 %", a rule of thumb from the first
   commit), `RUBBING_FLOOR_MM_TOOTH`, hardwood K_r, any burn threshold, the deflection target.
