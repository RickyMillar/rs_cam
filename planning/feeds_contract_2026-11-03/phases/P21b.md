## 2. The shape

- Engine: `SpindleStrategy::ConstantChip { rpm_ceiling: Option<u32> }` (section 5: the enum
  stays `Copy`). No serde on the engine enum.
- File: two flat keys of `[job.post]` (section 5). `PostConfig::spindle_strategy` is now the
  token enum `SpindleStrategyKind` (`match_chart`, `constant_chip`), and
  `PostConfig::spindle_rpm_ceiling: Option<u32>` is new (`skip_serializing_if = None`: an old
  file loads and saves as it was). `PostConfig::spindle_policy()` builds the engine value; every
  Suggest reader takes it (core session, viz pills, compare, the panel inputs, CLI, tests).
- The token enum keeps the ceiling under `MatchChart` too, so a switch to Match chart and back
  does not lose the operator's value. The GUI event carries the two keys for the same reason.
- Q16: `max_speed` refuses at load (`SpindleStrategyKind::from_token`, the text
  `MAX_SPEED_TOKEN_RENAMED`). No alias; nothing converts.
- Domain (the lead's rule): a ceiling of 0 refuses at the door (`SetPostConfig`,
  `DomainRefusal::Post(PostDomainError::RpmCeilingZero)`) and at load. A ceiling above the spindle
  maximum warns, never refuses: one sentence, `gcode::rpm_ceiling_above_spindle`, read by the
  loader (`ProjectLoadWarning::RpmCeilingAboveSpindle`), the GUI row (Caution state, hover), the
  MCP reply (`warning`) and the CLI (`warn!`).
- WP17: `spindle_rpm_ceiling` joins the exempt list of `post_change_reaches_motion` and the
  per-field rule of `set_post_config`.
- GUI: one "RPM ceiling" row under "Spindle policy", drawn under Constant chip or while a value is
  set. Empty is no ceiling (grey "none", a clear action). The range starts at 1, so the row never
  writes 0.
- MCP: `set_spindle_strategy { strategy, rpm_ceiling }`; feature token `spindle_rpm_ceiling`.
- CLI: `project --spindle-strategy constant_chip --spindle-rpm-ceiling <rpm>`.
- Kept for P21c: `SpindleScaleReason::MaxSpeedPolicy`, the step names `step2b_max_speed`, the two
  constants in the GUI hover, the assertion text of the tier tests.
