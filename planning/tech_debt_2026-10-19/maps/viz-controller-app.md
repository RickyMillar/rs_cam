## 1. Purpose and file map

Purpose. `controller` is the bridge from a UI intent (`AppEvent`, `UiCommand`) to `ProjectSession::apply(Command)`. It also owns the compute-lane submit/drain, the generation plan (Generate All) driver, toasts and the GUI runtime mirror of results. `app` is the egui shell (`RsCamApp`): per-frame loop, input, viewport draw, GPU upload, live-simulation playback, GUI export, and the GUI-thread half of the embedded MCP server (request dispatch, wire-to-`Command` conversion, JSON replies). The MCP server thread and wire types live outside the scope (`mcp_bridge.rs`, `mcp_server.rs`, `rs_cam_mcp`). Core owns the data model, the order of a generation plan and the freshness answer. This area mirrors them into `AppState.gui`.

## 3. Dependencies and layering

Imports (counts of `crate::X::` in non-test code): controller: state 121, controller 56, compute 43, mcp_bridge 29, ui 27, io 5, ui_command 2, error 2. app: state 121, ui 117, render 44, controller 38, mcp_bridge 21, compute 19, io 15, interaction 11, ui_command 6. `rs_cam_core` use is heavy in both: session 137, compute 84, feeds 56, geo 41, stock 40, trace 34.

Layering inversions and smells:
- **controller depends on ui for domain logic.** `controller/events/compute.rs:231-233` calls `ui::properties::validate_toolpath_config` and `ToolpathValidationContext` to refuse a submit. `controller/events/undo.rs:184,188` call `ui::properties::{part_models_first, stock_edit_command}`. `controller/events/model.rs:11` imports `ui::properties::pins::{KeyedPinInputs, keyed_pin_plan}`. `model.rs:746` imports `ui::properties::stock_changes::StockChangeIntent`. `controller/events/mod.rs:487-489` calls `ui::overlays::registry::{row, set_overlay}`. `controller/events/preferences.rs:26` imports `ui::preferences::*`. - **controller builds MCP JSON.** `controller/events/compute.rs:2345` `build_mcp_diagnostics` and the `notify_mcp_*` fns (2202-2600) build `serde_json` values inside the controller. Compute.rs holds 25 `json!` sites.
- **app depends on render GPU types and domain logic in the upload path.** `app/gpu_upload.rs:465-530` holds ProjectCurve surface projection and Trace level logic (`OperationConfig::Trace/ProjectCurve` arms, `SpatialIndex::build_auto`) in the GPU upload function.
- **`#[cfg(feature = "mcp")]`** gates: 24 blocks in `controller/events/compute.rs`, 8 in `controller.rs`, 21 in `app.rs`. `mcp` is a default feature (`Cargo.toml:40`), so the non-mcp build is a second configuration (`lib.rs:220` `no_mcp_feature_tests` exists).
- `app/mcp/` reads `AppController` through `self.controller.state()` (169 sites, per comment `app.rs:~780`) and calls `session.apply` directly in 4 places (see section 5).
- MCP lifecycle code (host exit, watchdog) lives in `mcp_lifecycle.rs`, `host.rs`, `mcp_server.rs`. Its doc is `app/mcp/CLAUDE.md`.
